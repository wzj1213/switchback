这份（kimi/）相比根目录那版改了什么

跟手「还不够丝滑」的根因找到了：拇指和填充各挂着一条 190ms 过渡，而生长/拖动时目标位置每帧都在变——过渡一直在追一个会跑的目标，永远慢半拍，那就是拖尾巴。现在生长、拖动、播放期间位移零过渡（1:1 跟手），松手落档那一下才恢复 190ms——过渡只留给「收得住」的瞬间。拇指位移从 left 改成 translateX（走合成器，不触发排版）；pointermove 合并进 rAF，一帧最多算一次；按压缩放改用独立的 scale 属性，位移和缩放各演各的。

对比加了 ②–⑤ 四个对比框：同一份 wireUp 跑五个实例，差异只在 CSS 变量——科技蓝、梦幻粉、熔岩橙、墨色，紫色不下放。

性能扫光的「无限绕圈」从 JS 挪进了 CSS keyframes。上一版页面挂着一条常驻 requestAnimationFrame：每秒醒 60 次，每帧还 getBoundingClientRect() 一次，哪怕什么都没在动。现在 JS 只在「长出」（620ms）和「收回」（300ms）两段里跑 rAF，跑完就停——不开 ultra 的时候，这个页面一帧 rAF 都没有；绕圈交给合成器。

性能尺寸监听换成 ResizeObserver：输入框真变了才重算周长和扫光起点，不再每帧量。星点重铺按 8px 量化：条子生长的 320ms 里不再每帧重建十几个 DOM 节点。

键盘模型菜单补上了方向键：↑↓ 展开并移动焦点，Home/End 跳首尾，Esc 收起并把焦点还给触发器，选中后焦点也回到触发器——上一版菜单只能用鼠标，和它自己底部的「键盘」说明对不上。

降级prefers-reduced-motion 补全：上一版只关了星点闪烁和绕圈高光，条的 320ms 生长、拇指滑动、扫光长出照跑。现在这些全部即时切换，颜色信息保留。

修跳变扫光收回从当前长度开始收。上一版写死从 100 收：长出到一半被打断（比如划出 ultra 又划回来），描边会「啪」地跳满再开始退。

四个对比框是怎么换皮的

②–⑤ 和 ① 跑的是同一份 wireUp(comp)，一行行为代码都没改——所有差异都是 CSS 自定义属性：--eff-0/1/ink/soft/ring 一套色、--eff-mid 给坡道加第三种颜色、--orbit-dur 扫光速度、--twk-dur 粒子节奏、--star-radius / --star-glow / --star-color 粒子形状、光晕和颜色。能这样换皮，说明原案的主题化是干净的：逻辑里没有一处写死的颜色。

对比度也验过（都是白底文字，4.5:1 是底线）：科技蓝 #1c5fd0 5.8:1、梦幻粉 #c2437f 4.8:1、熔岩橙 #c2410c 5.2:1、墨色 #16161a 15:1。梦幻和墨色那道环用了比坡道更深的 --eff-ring——直接用坡道末端的浅色描环，在白底上站不住；墨色深底时星点翻成深色（--star-color），不然白星落在白填上。

节奏也是主题的一部分：科技蓝把节拍调快（扫光 3.2s、闪烁 1.8s、方形粒子），要「精密仪器」；梦幻调慢（6.5s、3.8s、柔光圆点、三色极光），要「氛围感」；熔岩橙和墨色不动节拍——语义已经够响了，不需要节奏帮着喊。

五个里我会怎么选

如果那道口子要开：④ 熔岩橙最师出有名。橙是界面里说「警告 / 花销」的通用语，和 ultra 那句「更快消耗使用额度」是同义反复——用户不用学。① 紫靠的是「这个界面里没有紫」的稀缺性，口子一开、彩色一多，稀缺就没了；橙靠的是语义，语义不会过期。

如果不开：⑤ 墨色就是那个答案。不靠色相，靠黑度和描边——零彩色，合 tokens.css 的原规矩，「这档更贵」由那条最重的黑来说。代价也实在：它不再「响」，忘了关的时候，那圈黑描边比彩环好忽略得多。

② ③ 的问题是语义反着来。蓝在这套界面里是「信息 / 链接」（--accent），粉是「装饰 / 氛围」——都不说「钱」。绿没进对比：绿是 --ok，是「通过」，拿来标「烧钱」是撒谎。红也没进：--danger 是「出错」，而 ultra 不是错误，是用户自己的选择——选它不该被当成出事故。

行内条比卡片好在哪、差在哪

好在没有第二个平面。卡片是浮在界面上的一层，行内条就在你眼睛已经在的那一行——改完档位，视线不用回收。

好在那段空地本来就闲着。Kimi Code / 自动审批 / K3 / 最高 靠左、发送键靠右，中间那 300 多 px 一直空着——这条是唯一一个「不占新地方」的方案。

定宽 180，不是「剩多少占多少」。铺满到发送键那一版试过，三个毛病：左边四颗控件读起来像被挤到角落；宽度随模型名长度变（GPT-5.6 Sol 比 K3 宽 60px，条子就短 60px）；6 档摊在 319px 上每档 59px，比它需要的精度宽了一倍多。180px 下每档 32px，够点了。

差在窄窗口下还是得让步：空地不够 180 就用空地，下限 96px。卡片那版是固定 262px，不看窗口脸色。

差在装不下字。「更快 / 更聪明」两个端点标签没地方放，「更快消耗使用额度」也没有——26px 高的一条只放得下条子本身。

「更快消耗使用额度」不占一行了。上一版把它放在档位行下面，一到 ultra 整个输入框长高 18px，把上面的转录区顶走一截——为了说一句话，把你正在读的东西挪了位置。现在它挂在触发器的 title 上，鼠标停一下就有；而「这一档更贵」这句话，彩色和那圈扫光已经说过了。要那行字常驻可见的话，卡片那版有地方放，行内这版没有——这是两版之间一个实打实的取舍。

宽度为什么要 JS 量，不能靠 flex

flex: 1 加过渡是不行的：flex-basis 从 0 到 auto 没法平滑插值，那条会「啪」地弹到位——和「往右长出来」正好相反。

所以是：开之前量一下那段空地有多宽（.gapx 的实际宽度减掉一个 gap），把这个 px 值写到条子上，让 width 走 320ms 的缓动。窗口尺寸变了要重量一次，量的时候得把条子自己已经占的那部分加回去，不然越量越窄。

彩色是 ultra 一家的，普通档走中性灰

从最低档就开始铺彩，等于把「更贵」那句话说了六遍——说六遍就等于没说，真到 ultra 反而没有升级空间了。这条推理这个仓库写过两次：status.css 说「一刻不停的动画会持续抢注意力」，tokens.css 的用量表那段说「一直是彩色的话，真到危险区就没有升级空间了」。

而且引擎不报 ultra 的话，这套彩色从头到尾都不出现。换成 K2.7 试一下：它报三档，条子推到头也还是灰的——不是「灰色版的 ultra」，是这个模型根本没有那一档。（②–⑤ 同理：颜色跟着「报了 ultra」走，不跟主题走。）

它凭什么这么响

理由是：ultra 是这一行里唯一一个会明显改变花销的开关。ModelPicker.tsx 的 EFFORT 表里，六档只有它带说明，原文就是「更快消耗使用额度」——那行字是抄的，不是我编的。它不是「再强一点」，是「这一轮开始烧钱了」。

那道慢绕的高光不是庆祝动画，是常驻提示：你要是忘了自己开着这一档，这一圈会一直提醒。prefers-reduced-motion 下高光和星点闪烁都不出现，颜色、渐变、柔光留着——降级之后信息不丢。

还有一条要你拍板：tokens.css 开头写着「强调色只用于焦点与链接；主按钮用近黑，不用彩色」。这根彩条是这套界面里第一处大面积的、非内容语义的颜色。我认为它值——它标的是花钱；但它确实是对那条规矩开的第一个口子，得是有意开的。②–⑤ 四个配色是「如果开，还能是什么颜色；如果不开，长什么样」的参照系——⑤ 就是「不开」的那个答案。
