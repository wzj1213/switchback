五方改了什么 —— 逐条分开列

署名每条前面标了是谁改的。kimi、Claude 和 Grok 那几条原样留着，不是重写。⑫–⑭ 和 ⑮–⑰ 是我（GLM）两轮加的，前十一套的 CSS 一个字没改——新变量不设就落回原样。

跟手（kimi）「还不够丝滑」的根因找到了：拇指和填充各挂着一条 190ms 过渡，而生长/拖动时目标位置每帧都在变——过渡一直在追一个会跑的目标，永远慢半拍，那就是拖尾巴。现在生长、拖动、播放期间位移零过渡（1:1 跟手），松手落档那一下才恢复 190ms——过渡只留给「收得住」的瞬间。拇指位移从 left 改成 translateX（走合成器，不触发排版）；pointermove 合并进 rAF，一帧最多算一次；按压缩放改用独立的 scale 属性，位移和缩放各演各的。

对比（kimi）加了 ②–⑤ 四个对比框：同一份 wireUp 跑多个实例，差异只在 CSS 变量。能这么换，说明主题化是干净的——逻辑里一处写死的颜色都没有。

性能（kimi）扫光的「无限绕圈」从 JS 挪进了 CSS keyframes。上一版页面挂着一条常驻 requestAnimationFrame：每秒醒 60 次，每帧还 getBoundingClientRect() 一次，哪怕什么都没在动。现在 JS 只在「长出」（620ms）和「收回」（300ms）两段里跑 rAF，跑完就停——不开 ultra 的时候，这个页面一帧 rAF 都没有；绕圈交给合成器。

性能（kimi）尺寸监听换成 ResizeObserver：输入框真变了才重算周长和扫光起点，不再每帧量。星点重铺按 8px 量化：条子生长的 320ms 里不再每帧重建十几个 DOM 节点。

圆口（Claude）展开途中它压根不是一枚胶囊：overflow: hidden 切出来是平口，只有到位那一帧才突然圆起来。改用 clip-path: inset(… round 13px)，切口自带圆角，全程都是完整的一枚。

定宽（Claude）条子原来是 width: 100%，父容器每帧变宽它就每帧变宽，所以得有个 follow() 每帧 paintBar()。现在宽度一次给定（--bw），位置一次算完——那圈 rAF 整个删掉了，展开期间 JS 一帧都不跑。这一条和 kimi 那条「绕圈挪进 keyframes」是同一个方向：能交给合成器的别放在 JS 里。

手感（Claude）收起 200ms、展开 300ms——关掉一个东西不需要被欣赏。展开时拇指和填充从最左跟着 clip 一起走，看起来是拇指把条子拽开的，不是条子露出来一个静止的拇指。

修（Claude）#i-folder 那条 path 在 kimi 那版是坏的：V12a1 1 0 0 1-1-1H3 的弧线终点落在 y=11，文件夹的底边被抬起来一截。正确的是 -1 1H3。

新机制（Claude）为 ⑥⑧ 两套加了两个变量：--eff-mid-at（三段坡道里中间那站停在哪儿）和 --sheen（填充上扫过去的高光）。都不设就落回原样，前五套一个字没动。

刃口（Grok）彩色只停在条子右端那一截。电石已经把色相憋到最后一档，但涌上来之后整段填充还是彩的；这一套把「彩色是 ultra 一家的」再往下压一档——连这一档内部，彩色也只是刀锋，不是整段。新变量 --edge，不设整层不画。

刻度（Grok）条子上画出和档位数相同的刻度。强度是离散的（3 档或 6 档），条子却一直装成连续坡道——档位只写在触发器的字上，条子自己并不说。JS 只多写一个 --gears（paint() 本来就知道 N），--ticks 不设就没有刻度。刻度是结构，不是皮，可以叠在任何一套上；这一框用近黑把它单独示意。

落点（Grok）输入框那圈扫光关掉，改去点亮发送键。滑块是偏好，真花钱的是按下发送的那一下。把「别忘了你开着 ultra」贴在 760px 的框上，是在用最大的那个平面喊一件发生在 28px 按钮上的事。同一份 wireUp，扫光环 JS 照跑，CSS 把它藏掉。

修（Grok）⑥ 墨金的扫光带宽写成 60%，但 paintBar() 把所有坡道层的 background-size 都写成了整条宽——高光条被拉扁，金就不再是「一道」而是「一层」。现在 sheen 自己管自己的尺寸。

补齐（GLM）我上一轮的稿子停在半路：⑫ 的框是空壳、⑬⑭ 两框没落地、「五方」这节的标题被顶掉了；JS 里 --heat 一个字没写，--hot-on 的选择器还写反了（.v-wine 是 .ibar 的祖先，.ibar--hot .v-wine 永远匹配不上）。这一轮全部补上——酒芯不渗、档灯死在最左，根因都是这两条。

地基（GLM）JS 只多写一个 --heat：paintBar() 本来就算出了当前进度（0–1，拖动中是连续值），现在把它写到条子上。⑫–⑭（浓度 / 档灯 / 呼吸）和 ⑮–⑰（拇指色温 / 坡道色温 / 残影）六个机制全部从它取值，前十一套不读它，一个字不用改。档灯用 round() 把它吸到格子中心：拇指说连续位置，灯说离散落点。

监听（GLM）「点别处收起」从每框一条 document 监听合并成整页一条（十七框原来挂十七条，做的却是同一件事）；resize 合并进 rAF——paint() 要读 clientWidth，拖窗口时一帧涌进好几个事件。和 kimi 那条 pointermove 合并是同一个毛病的两个入口：一帧排一次版。

酒芯（GLM）「非黑即紫」的二元切换改成连续浓度：前五档按档位淡渗（heat × 0.5），ultra 落档后吃满——「越往右越贵」从 ultra 独享的一句话变成一条斜坡，但终点还是那一档。

档灯（GLM）刻度（⑩）说有几个档，没说你落在哪格；这一信息一直只写在触发器的字上。灯钉在刻度层上跟着 --heat 走：拖动时一格一格跳（吸到格心，不骑刻度线），落档停在那格的肚里。

玫瑰金（GLM）墨金（⑥）的高光是有方向的「扫」，这一套试另一个词：呼吸——整段 6s 明暗 5%，没有方向、没有故事。玫瑰金是金属色里唯一没被前面用过的。

炽芯（GLM）前十四套把所有的话交给轨道，拇指一直是一颗中性的白圆——可拖动时眼睛盯的是拇指。轨道退回钢灰（零彩色），灯芯用 color-mix 随 --heat 变暖，ultra 落档烧亮＋铜描边（--thumb-glow 是 Grok 留的口子，直接用）。

曙光（GLM）坡道两站在 oklab 里从黎明前的蓝灰往日出挪，挪多少由 --heat 说了算：不落 ultra，条子永远「快亮了」而不是「亮了」。ultra 那层才是完整天亮：蓝灰 → 霞粉 → 金。

曳痕（GLM）六套里唯一的非常驻方案：条子平时灰 → 墨（和 ⑤ 同路），拖动时拇指后面拖出一道热痕（fill::after，零 DOM 改动），松手 1.6s 冷却——它说「刚才发生了什么」，「现在是什么」仍由落档后的墨条和描边负责。

键盘模型菜单补上了方向键：↑↓ 展开并移动焦点，Home/End 跳首尾，Esc 收起并把焦点还给触发器，选中后焦点也回到触发器——上一版菜单只能用鼠标，和它自己底部的「键盘」说明对不上。

降级prefers-reduced-motion 补全：上一版只关了星点闪烁和绕圈高光，条的 320ms 生长、拇指滑动、扫光长出照跑。现在这些全部即时切换，颜色信息保留。

修跳变扫光收回从当前长度开始收。上一版写死从 100 收：长出到一半被打断（比如划出 ultra 又划回来），描边会「啪」地跳满再开始退。

十七框是怎么换皮的

十七框跑的是同一份 wireUp(comp)，一行行为代码都没改——所有差异都是 CSS 自定义属性：--eff-0/1/ink/soft/ring 一套色、--eff-mid 给坡道加第三种颜色、--orbit-dur 扫光速度、--twk-dur 粒子节奏、--star-radius / --star-glow / --star-color 粒子形状、光晕和颜色；Claude 加了 --eff-mid-at / --sheen，Grok 加了 --edge / --ticks / --thumb-glow，GLM 加了 --heat（进度 0–1，⑫–⑭ 的浓度 / 档灯 / 呼吸、⑮–⑰ 的拇指 / 色温 / 残影都从它取值）。能这样换皮，说明原案的主题化是干净的：逻辑里没有一处写死的颜色。

对比度也验过（都是白底文字，4.5:1 是底线）：科技蓝 #1c5fd0 5.8:1、梦幻粉 #c2437f 4.8:1、熔岩橙 #c2410c 5.2:1、墨色 #16161a 15:1、刃口字 #7a5a10 6.4:1、落点字 #8a3b12 7.8:1、落点发送键白字压铜底 #9a4a20 6.2:1、炽芯字 #9a3412 7.3:1、曙光字 #7a5525 6.7:1。梦幻和墨色那道环用了比坡道更深的 --eff-ring——直接用坡道末端的浅色描环，在白底上站不住；墨色深底时星点翻成深色（--star-color），不然白星落在白填上。

节奏也是主题的一部分：科技蓝把节拍调快（扫光 3.2s、闪烁 1.8s、方形粒子），要「精密仪器」；梦幻调慢（6.5s、3.8s、柔光圆点、三色极光），要「氛围感」；熔岩橙和墨色不动节拍——语义已经够响了，不需要节奏帮着喊。刃口和刻度也不调节拍：一个靠位置（右端那一截），一个靠结构（格子），都不靠把动画喊得更响。

八个里我会怎么选

如果那道口子要开：④ 熔岩橙最师出有名。橙是界面里说「警告 / 花销」的通用语，和 ultra 那句「更快消耗使用额度」是同义反复——用户不用学。① 紫靠的是「这个界面里没有紫」的稀缺性，口子一开、彩色一多，稀缺就没了；橙靠的是语义，语义不会过期。

如果不开：⑤ 墨色就是那个答案。不靠色相，靠黑度和描边——零彩色，合 tokens.css 的原规矩，「这档更贵」由那条最重的黑来说。代价也实在：它不再「响」，忘了关的时候，那圈黑描边比彩环好忽略得多。

我自己那三套里：⑥ 墨金是我真会投的一票。它和 ⑤ 墨色同一条路——零彩色，合 tokens.css 那条原规矩——但补上了 ⑤ 唯一的短板：⑤ 忘了关的时候那圈黑描边太好忽略，而 ⑥ 有一道会动的金。「响」这件事交给运动，不交给色相：既不开彩色的口子，也不会被忽略。

⑧ 电石是三套里唯一带结构性想法的：色相只在最后一档涌上来，前四分之三是灰的。其余七套整条都在渐变，于是「越往右越贵」这句话从第一档就开始说——而真正贵的只有最后一档。它把「彩色是 ultra 一家的」这条推理从「档与档之间」下沉到了「一条之内」。但青绿离 --ok 太近，语义上有撞车风险，真要用得换个色相——这一条我认，它是个想法，不是个成品。

⑦ 深空好看，但我不会投它，理由和 ③ 梦幻一样：它没在说钱。留着是因为它回答了另一个问题——星点这个装置在前几套里更像噪点，只有铺在深靛底上才真读成星星。如果最后决定留星点，⑦ 是它唯一站得住的底色。

② ③ 的问题是语义反着来。蓝在这套界面里是「信息 / 链接」（--accent），粉是「装饰 / 氛围」——都不说「钱」。绿没进对比：绿是 --ok，是「通过」，拿来标「烧钱」是撒谎。红也没进：--danger 是「出错」，而 ultra 不是错误，是用户自己的选择——选它不该被当成出事故。

我（Grok）那三套里会怎么选

⑪ 落点是我会投的一票。前面十套都在条子上或框上喊「这档更贵」——可滑块是偏好，钱是按下发送那一下才走的。把常驻提示从 760px 的框挪到 28px 的发送键上，是把响度贴回动作发生的地方。它也不再给条子开大面积彩色的口子：条子可以继续走灰，发送键只在 ultra 落档之后才亮。

⑨ 刃口是如果「信号必须在条子上」我会投的那张。电石的推理是对的，但它涌上来之后整段还是彩的，等于最后一档又把「更贵」说成了整条的事。刃口把这句话收到右端那一截——钢灰是本体，色相是刀口。钨丝那点暖黄说的是「这段在发热」，不是警告橙，也不是装饰金。

⑩ 刻度不是一套皮，是一个该留下的结构。换 K2.7 试一下：三档的刻度立刻变成三格，这是前面十套谁都没说的信息。真落地的时候我会把它叠在 ④ 熔岩橙或 ⑥ 墨金上面，而不是单独用近黑这一框——这一框只是把结构亮出来给你看。

我（GLM）这六套里会怎么选

⑮ 炽芯是我会投的一票。⑪ 落点把提醒贴到发送键上，理由是「贴到动作发生的地方」——同一句话推到底：拖动这个动作发生在拇指上，热度却一直画在别处。轨道退回钢灰，等于顺带合了 tokens.css 那条零彩色的原规矩；灯芯从第一档就开始变暖，「越往右越贵」第一次不需要 ultra 在场也在说。

⑯ 曙光和 ⑫ 酒芯是同一句话的两种说法（浓度 / 色温），真落地选一个就好。我偏 ⑯：⑫ 的淡渗在低档位几乎看不见（前两档 opacity 不到 0.2），色温的挪动全程可读。它还顺手回答了星点的归属——⑦ 说星点只有铺在深靛上才成立，黎明是第二个说得通的底：天快亮了，星还没走。

⑰ 曳痕不能单独用，它补的是另一个缺口。残影说「刚才」，总得有谁说「现在」——落档后的墨条和描边就是那句常驻的话。它值得留的原因恰恰是所有常驻提示共同的毛病：会被看习惯；会冷却的残影不会。

行内条比卡片好在哪、差在哪

好在没有第二个平面。卡片是浮在界面上的一层，行内条就在你眼睛已经在的那一行——改完档位，视线不用回收。

好在那段空地本来就闲着。Kimi Code / 自动审批 / K3 / 最高 靠左、发送键靠右，中间那 300 多 px 一直空着——这条是唯一一个「不占新地方」的方案。

定宽 180，不是「剩多少占多少」。铺满到发送键那一版试过，三个毛病：左边四颗控件读起来像被挤到角落；宽度随模型名长度变（GPT-5.6 Sol 比 K3 宽 60px，条子就短 60px）；6 档摊在 319px 上每档 59px，比它需要的精度宽了一倍多。180px 下每档 32px，够点了。

差在窄窗口下还是得让步：空地不够 180 就用空地，下限 96px。卡片那版是固定 262px，不看窗口脸色。

差在装不下字。「更快 / 更聪明」两个端点标签没地方放，「更快消耗使用额度」也没有——26px 高的一条只放得下条子本身。

「更快消耗使用额度」不占一行了。上一版把它放在档位行下面，一到 ultra 整个输入框长高 18px，把上面的转录区顶走一截——为了说一句话，把你正在读的东西挪了位置。现在它挂在触发器的 title 上，鼠标停一下就有；而「这一档更贵」这句话，彩色和那圈扫光已经说过了。要那行字常驻可见的话，卡片那版有地方放，行内这版没有——这是两版之间一个实打实的取舍。

宽度为什么要 JS 量，不能靠 flex

flex: 1 加过渡是不行的：flex-basis 从 0 到 auto 没法平滑插值，那条会「啪」地弹到位——和「往右长出来」正好相反。

所以是：开之前量一下那段空地有多宽（.gapx 的实际宽度减掉一个 gap），把这个 px 值写到条子上，让 width 走 320ms 的缓动。窗口尺寸变了要重量一次，量的时候得把条子自己已经占的那部分加回去，不然越量越窄。

彩色是 ultra 一家的，普通档走中性灰

从最低档就开始铺彩，等于把「更贵」那句话说了六遍——说六遍就等于没说，真到 ultra 反而没有升级空间了。这条推理这个仓库写过两次：status.css 说「一刻不停的动画会持续抢注意力」，tokens.css 的用量表那段说「一直是彩色的话，真到危险区就没有升级空间了」。

而且引擎不报 ultra 的话，这套彩色从头到尾都不出现。换成 K2.7 试一下：它报三档，条子推到头也还是灰的——不是「灰色版的 ultra」，是这个模型根本没有那一档。（②–⑤ 同理：颜色跟着「报了 ultra」走，不跟主题走。）

它凭什么这么响

理由是：ultra 是这一行里唯一一个会明显改变花销的开关。ModelPicker.tsx 的 EFFORT 表里，六档只有它带说明，原文就是「更快消耗使用额度」——那行字是抄的，不是我编的。它不是「再强一点」，是「这一轮开始烧钱了」。

那道慢绕的高光不是庆祝动画，是常驻提示：你要是忘了自己开着这一档，这一圈会一直提醒。prefers-reduced-motion 下高光和星点闪烁都不出现，颜色、渐变、柔光留着——降级之后信息不丢。

还有一条要你拍板：tokens.css 开头写着「强调色只用于焦点与链接；主按钮用近黑，不用彩色」。这根彩条是这套界面里第一处大面积的、非内容语义的颜色。我认为它值——它标的是花钱；但它确实是对那条规矩开的第一个口子，得是有意开的。②–⑤ 四个配色是「如果开，还能是什么颜色；如果不开，长什么样」的参照系——⑤ 就是「不开」的那个答案。
