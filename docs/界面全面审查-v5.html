下面正文是改之前的实测，一个字没动——留着是因为每一条都记着为什么， 下次有人想把某个值改回去时，理由在这儿。已落地的部分：

  • A5 按下态：app-foundation.css 加 :where() 兜底（(0,2,0)，输给任何写明的 :active），实心主键各自写明。20 处低于 28px 的点击区改用溢出伪元素撑热区 → 实测 20 → 2。
  • A3 时长：新增 --dur-fast / --dur-bar，散落的 70/220/320 全部收回。编排动画与角色动画按判据留在表外并说明。
  • A1 字号：46 处「要读的字」从 11.5 提到 13。实测转录区 13px 成为主力（29 处），11.5px 从 23 降到 10，≤12.5px 占比 58% → 42%。
  • A6 图标：八处裸 <svg> 收回 Svg；七处 ×/✕ 换 CloseIcon；新增 scripts/check-icons.mjs 串进 pnpm check。
  • A2 圆角：十六处非 token 值按「它到底是什么形状」归位（胶囊 / 圆点 / 微记号 / 同心算式），实测零处非 token 圆角。
  • B1 B2 B5：立 --bar-w，四条横带回到同一条居中基准（实测四带同为 467），断言写进 01-转录区；输入卡下沿留够阴影。
  • B4：空态去掉装饰圆、改为锚在输入框上（标题 32% → 46%，间距 43% → 28%，对上 codex 的 44/30）。
  • C1 C2 C3 C4：侧栏文字列四条 → 一条（32）；段头 43 → 26；新增 ⌘\ 折叠与「显示」菜单；身份行显示名字 + 套餐。
  • E4：设置面板从定高 660 改成按内容长。

没做的两条，各有理由：
· B3 顶栏进正文列——照做的话侧栏展开时顶栏左边会空出 187px，比现在更糟。
· E6 控件规格拉齐——.trigger 的「平时是文字、悬停才成胶囊」是 popover.css 里写明的决定， 改它是拿我的口味换掉一条有据的决定，不是修缺陷。
· A4 硬编码间距——其中绝大多数是 8px 以下的微值（图标与箭头之间的 3px 之类）， 和 --radius-mark 同一类：--sp 阶梯从 4 起步，本来就管不到那一档。

另有一条正文没提、做的时候才发现的：出图套件本身在任何工作区状态下都跑不完 （四条断言隐含假设了工作区是某个形状，其中一条还是自指的——它扫 diff 正文找一个字符串， 而含有那个字符串的文件正是它自己）。修完之后浅色 / 深色 / 最小窗口三档各跑一遍全过， 这是这个仓库第一次三档都能跑完。

这套界面欠的不是设计，是把已经写在注释里的决定收敛到数字上。tokens.css 声明 5 档字号、4 档圆角、2 档时长、6 档间距；实际渲染出来是 7 档字号、10 种圆角、6 种时长，外加 239 处硬编码 px。 最小那档字号（11.5px）占了全部字号声明的 55%，而「要读的」14px 只有 11 处——和 codex 并排显小气， 原因不是没选过字号，是选好的那张表没被用起来。同一件事在图标上、按下态上、左缘上各发生了一遍。

怎么测的

用仓库自带的 scripts/shot-app.mjs 起 Electron + CDP，在固定样本上连拍 58 屏（浅/深/最小窗口三套）， 再用一份 Runtime.evaluate 探针读全树的 getComputedStyle 与 getBoundingClientRect。 下面每一个数字都是那次实读，不是估的。窗口 1440×900、2× 屏、经典滚动条档位。

B2 · 那 5px 是上一轮 scrollbar-gutter 引进来的

UI细节优化计划.md 第 6 条给 .transcript 加了 scrollbar-gutter: stable， 理由完全正确（滚动条冒出来时正文列会向左跳）。但 .composer 没有跟着加：

/* app-main.css:156 */
.transcript { padding: var(--sp-5) var(--sp-4) var(--sp-6); scrollbar-gutter: stable; }
.transcript__inner { max-width: 760px; margin: 0 auto; }

/* items-composer.css:10 —— 没有 gutter */
.composer { padding: var(--sp-2) var(--sp-4) var(--sp-4); }
.composer__inner { max-width: 760px; margin: 0 auto; }

经典滚动条档位下 ::-webkit-scrollbar 宽 10px，于是转录区的内容盒比输入区窄 10px， 两个居中的 760px 列因此差 5px。再叠上输入卡自己的 1px 描边 + 12px 内边距， 你打的字比 agent 的回答右移 18px。

为什么这条一直没被发现

它只在插了鼠标的时候出现。macOS「自动根据鼠标或触控板」这一档， 用触控板时是叠加条、gutter 恒为零、两列完全对齐；插上鼠标才切经典条，5px 才冒出来。 出图脚本跑在同一台机器上，所以这一档一直被拍进图里，只是没人拿尺子量。

/* 修法：把两列的居中基准变成同一个。改 items-composer.css:10 */
.composer {
  padding: var(--sp-2) var(--sp-4) var(--sp-4);
  scrollbar-gutter: stable;   /* 和 .transcript 同一个理由的另一半 */
}
/* 再把输入卡的内边距从盒子挪成「文字对齐正文列」：
   卡片仍然 760 宽，但左内边距吃进 max-width，让 caret 落在 467 而不是 485 */
.composer__inner {
  max-width: var(--content-max);
  max-width: calc(var(--content-max) + var(--sp-3) * 2 + 2px);
  padding: var(--sp-2) var(--sp-3);
}

验收：插鼠标 + 触控板各拍一张 01-转录区，用探针断言 .md 与 .composer__input 的 left 相等（现在差 18）。这条断言值得直接写进 shot-views.mjs。

B3 · 顶栏与正文列脱节

顶栏标题在 x=280，正文在 467——中间 187px 空白。顶栏高 44px、padding: 0 16px， 它排的是「窗格」，正文排的是「列」，两套坐标系。

建议：顶栏内容也进 760 列（.topbar 内加一层 max-width: var(--content-max); margin: 0 auto， 用量表和动作按钮 position: absolute 靠右）。这一条改完，标题 / 回答 / 输入框三条横带的左沿终于在一条线上—— claude 与 codex 两张图里都是这么排的，这是它们「看起来是一个整体」的主要原因。

B4 · 空会话：标题和输入框不是一组

实测（1440×900）：大标题 .blank__title 在 y≈340，输入框顶 y=735，中间 340px 纯空。 .blank 写着 min-height: 55vh; justify-content: center，它在转录区里居中， 而转录区是「输入框以上的全部」——于是标题被推到全窗口的 38% 高处，和输入框各据一方。

/* app-main.css:631 */
.blank {
  justify-content: center;
  min-height: 55vh;
  justify-content: flex-end;      /* 沉到底，和输入框成一组 */
  padding-bottom: var(--sp-6);    /* 与输入框之间只留一个段距 */
}

顺带：.blank__glyph 是个 62px 的空心圆套一个终端图标。 建议整个删掉——codex 那屏没有图标，claude 那屏也没有；一个 62px 的装饰圆在 「你想做点什么」上面，既不指示状态也不可点，只是把标题连同它下面那一整组往下压了 70px。

B5 · 输入框贴死窗口底沿

.composer 的下内边距是 --sp-4（16px），而卡片本身有 --shadow-composer 向下扩散 24px——阴影被窗口边缘切掉，卡片看起来是「长在窗框上」而不是「浮在纸上」。 改成 --sp-5（24px）能让那层环境影完整落地。深色下阴影关闭，这 8px 也仍然值： 它是「这张卡是独立一层」的唯一证据。

C3 · 没有折叠侧栏的入口

全仓搜不到任何收起侧栏的控件。侧栏固定 264px，只有在工作台打开且窗口 ≤1280px 时才被 CSS 自动隐藏 （app-foundation.css:150）。实测最小窗口 900px 宽时，侧栏吃掉 29.3%，正文列被压到 430px， 代码块横向溢出——而用户没有任何办法把它收起来。

claude 与 codex 两张图里，左上角第一颗按钮都是侧栏开关。建议：

  • 顶栏最左（交通灯右侧）加一颗 PanelLeftIcon，与右侧那颗工作台开关成对；
  • 快捷键 ⌘\（claude / codex / vscode 三家一致）；
  • 收起后主栏 padding-left: 92px 给交通灯让位——这段逻辑 app-foundation.css:172 已经写好了，直接复用。

C4 · 底部身份行显示的是 a1b2c3d4e5@privaterelay.appleid….

SidebarFoot.tsx 的设计是对的（一行、左身份右动作、无账号时整行变「设置」）。 问题只在取什么字：Apple 中继邮箱在 264px 宽的行里必然被截成一串乱码， 而 claude 那张图里是「alice · Max」。

  • label 超过 18 字符时只取 @ 前面的本地部分；本地部分本身像随机串（无元音／长度 >12）时退回引擎报的 display name；
  • plan 报得上来就跟在后面（名字 · Max），这一行现在是空的，而它正是最该被一眼看到的东西；
  • 完整邮箱留在 title 和弹出菜单抬头里——那两处本来就有。

D图标

D1 · 八处裸 <svg> 收回 Svg

见 A6 的实测表。改法是机械的，但有一条不能省：不要只把 strokeWidth 删掉—— Svg 只在 <svg> 元素上设 strokeWidth，子元素若自带 stroke-width 会盖掉它。 review.css:107 / 153 那两条是写在 CSS 里的，必须删掉整条声明，而不是改数值。

/* TopBarActions.tsx —— 从裸 svg 收回 icons.tsx */
function PanelIcon() {
  return <svg width="14" height="14" viewBox="0 0 16 16" fill="none"
    stroke="currentColor" strokeWidth="1.5" aria-hidden="true">
    <rect x="2" y="2.5" width="12" height="11" rx="2" />
    <path d="M10.5 2.5v11" />
  </svg>
}
/* icons.tsx 里加一枚，两处（顶栏 / 工作台）共用同一个形 */
export function PanelIcon({ size }: { size?: number } = {}) {
  return (
    <Svg size={size}>
      <rect x="2" y="2.5" width="12" height="11" rx="2" {...LINE} />
      <path d="M10.5 2.5v11" {...LINE} />
    </Svg>
  )
}

/* review.css —— 删掉这两条，交给 Svg 算 */
.rv__tool svg { width:14px; height:14px; fill:none; stroke:currentColor;
  stroke-linecap:round; stroke-linejoin:round; stroke-width: 1.35; }

D2 · 加一条守卫，让这件事不再长回来

这是第二次修同一个毛病了（icon-base.tsx 的注释记着第一次）。 仓库已经有 check-tokens.mjs / check-css.mjs 两条守卫，缺的是这一条：

// scripts/check-icons.mjs —— 串进 pnpm check
// 判据：renderer 下除 icon-base.tsx / pets-art.tsx / dsh-art.tsx / composer-ring.tsx
// 之外，任何 .tsx 里出现 `<svg` 或 `strokeWidth=` 即失败；
// styles/*.css 里出现 `stroke-width:` 即失败（那是 Svg 的职责）。
// 豁免名单写在文件里并注明理由 —— 照 check-css.mjs 的 INTENTIONAL 写法。

豁免的四个是真正的插画（桌宠、DSH 形象、输入框那圈渐变环），它们不是图标，不该受 1.25px 约束。

D3 · 尺寸档也该收敛

icon-base.tsx 定了 SIDEBAR_ICON = 15 / SIDEBAR_ICON_SMALL = 12， 但组件里散着 size={11}、{13}、{14}、{34}。建议在 icon-base.tsx 再立三个名字， 把「多大」也变成有限档：ICON_INLINE = 13（正文里的）、ICON_UI = 15（控件里的）、ICON_HERO = 34（空态）。 和字号一样，档少的好处不是省事，是让「这两个不该一样大」变成一个要写理由的决定。

E交互细节

E1 · 补齐按下态（收益最大的单项）

110 处 hover / 23 处 active。不必逐个补——把它做成一条基线规则：

/* app-foundation.css 顶部，紧跟 svg 那条全局规则 */
/* 能点的东西按下去都要有一档。个别控件（主按钮、危险按钮）自己覆盖。 */
button:not(:disabled):active,
[role="button"]:not([aria-disabled="true"]):active,
summary:active {
  background: var(--bg-press);
}

然后逐个排除三类：底色本来就深的主按钮（改 opacity: .88）、 危险确认键（.row__act--danger，它按下去要更红不是更灰）、 以及输入框内的 .trigger（它按下会弹菜单，菜单出现本身就是反馈——但仍建议给 60ms 的按下态， 弹出有延迟时那 60ms 是唯一凭据）。

为什么优先做这条

A1–A4 那几条是「看起来不精致」，这一条是「用起来觉得没反应」。 你说的「各种交互感觉差很多」，绝大部分是它。而且它是全局一条规则的事， 不需要出图比稿——按下去有没有一档灰，肉眼在真机上一秒就判得出。

E2 · 时长收敛到三档

/* tokens.css —— 补第三档，删掉散落的 0.07 / 0.22 / 0.32 */
--dur-fast: 70ms;   /* 按下态、hover 底色：要跟手，慢一点就是「粘」 */
--dur: 120ms;       /* 浮现、淡入淡出 */
--dur-slow: 240ms;  /* 位移、展开 */

0.07s 已经在用（5 处），只是没登记；items-composer.css:101 的 220ms 归 240ms； --bar-fade: 320ms 是滚动条淡出，那是刻意慢的，保留但改成 token（--dur-bar）并写明理由。

E3 · 点击区抬到 28

.sidebar { --sb-act: 22px; --sb-act: 26px; }   /* 图标仍 15，四边各 5.5 */
.iconbtn { width:26px; height:26px; width:28px; height:28px; }

搜索行那条不一样：.sidebar__filter 只有 17px 高是因为 input 没被拉满， 外面 34px 的 .row--search 里上下各 8px 点不进去。height: 100% 一行解决。

E4 · 设置面板定高 660px，多数页面撑不满

settings.css:33 是 height: min(660px, 100%)。实测「通用」页只有两张卡（约 200px 内容）， 下面 460px 全空；而「引擎」「环境」两页要滚。shot-app.mjs 自己的注释也记着这个现象。

.set {
  height: min(660px, 100%);
  min-height: 380px;
  max-height: min(660px, 100%);
}

加下限是为了不让「通用」页缩成一张小卡——左侧那列有 8 个页签，面板比页签列还矮会很怪。

E5 · 密度倒挂：把次级信息从「更小」改成「更淡」

A1 的分布问题，落到具体改法上是一条替换规则：

现在改成典型位置
--text-xs + --text-faint--text-sm + --text-faint侧栏时间、行内计数、工具行的次级名
--text-xs + --text-muted--text-sm + --text-faint卡片抬头、段说明
--text-xs保留真角标：+12 −3、2/3、徽标里的字

换句话说：11.5px 从「次要」的意思收回成「角标」的意思，次要交给颜色。 这一条动的地方多（163 处里大约一半），但每一处都是同一个判断，可以一次性做完再出一轮图比。

E6 · 投入不均：一个高保真控件，一屋子裸控件

app-composer.css 844 行里，推理强度滑块独占约 400 行， 带内阴影、渐变轨道、品红警示色（#96307c / #b4409a）、三段 clip-path 动画。 它做得很好——但它是全应用唯一这个规格的控件，旁边的引擎选择器是一行无边框文字。 两者并排时，眼睛读到的不是「这个更重要」，是「这两个不是一个应用里的」。

两条路选一条，不要都不选：

  • 要么把它降下来：保留渐变刻度（那确实在说「越往右越贵」），去掉内阴影与拟物高光， 品红收进 --warn／--danger 语义色；
  • 要么把旁边抬上来：.trigger 给一层 --bg-raised + 发丝边， 让输入框底排的四个控件成为同一族。

我倾向第二条：滑块的高保真是有理由的（它是唯一一个「拖着调、且调错要花钱」的控件）， 问题不在它太重，在别的太轻。

不建议做的三件事

  • 不要换基调。 纸＋墨、面不分层、强调色只给焦点与链接——这套决定是对的， 上面所有条目都不动它。看起来「差」的从来不是色板。
  • 不要给桌宠让路，也不要把它挪走。 它现在浮在输入框上沿、和转录区最后一行重叠。 但那是它自己的设定（站在输入框这条地面上），改成侧边或角落会让它变成一个贴纸。 真要改就只改一件事：转录区最后一个块与桌宠之间加一个 --sp-6 的下摆，别让文字从它脚下穿过去。
  • 不要顺手加命令面板（⌘K）。 已经有 / 面板了， omniCommands.ts 的注释写明「再复制一份到命令面板只会有两处状态要同步」。这条结论仍然成立。
