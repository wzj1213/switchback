A2 / 会话行那份稿子的第 1 条 · 内核采纳，实现改写

会话行的右半边一直是空的

它稿子里说的「状态点」omni 早就有了，还会呼吸（.row__dot--running + dot-breathe），「待批准」四个字也一直在写（.row__note）。真正新的那半条是右侧的时间——而那一格今天是空的。

A3 / 顶栏那份稿子的第 3 条 · 一半采纳，一半驳回

顶栏不说「谁在答我」

omni 的整个立意是「一个界面统一驱动各家引擎」。而「此刻是谁在答」这件事，界面上唯一说出口的地方是输入框最底下那颗下拉——离你正在读的回答 600px 远。

先更正它的前提

它稿子里写「原来整根栏只有一个 omni ⌄」。这句是错的——顶栏是条件内容，截图那一刻恰好只有两样在。TopBar.tsx 实际装着：

.topbar__title    会话标题，点开是环境卡（title="环境信息"）
.badge--muted     历史记录      thread.detached 时
.badge            接力 N 手     engineHistory.length > 1 时
ContextMeter      51.9k / 262k
LimitPill         额度 87% · 本周 快用完时才出现
.iconbtn          对比分叉      peer 存在时
.iconbtn          分叉到 codex  有下一家时

缺的只有一样：thread.engine —— 当前引擎的名字，从来没在这儿出现过。

采纳：加一枚引擎徽章。这是那份稿子里最值钱的一条。放在标题右边——「我在哪个会话里」和「这个会话由谁在跑」是同一个问题的两半，和标题挂环境卡是同一条理由。

  • 形制用已有的 .badge：描边胶囊、--text-muted、11.5px、永远不可点。items/app.css 已经立过这条规矩——「徽章只说明状态；可点的是 .iconbtn 或 .trigger，两者长得一样的话『能不能点』就没有任何视觉线索了」。换引擎仍然只在输入框那颗下拉里。
  • 驳回它的 --accent-soft 蓝底胶囊。tokens.css：强调色只用于焦点与链接。而且蓝底会让引擎徽章比旁边的「接力 3 手」重一档，那两枚是同类。

采纳：52 → 44px。但理由和它写的不一样——不是「从装饰变成工具」（它本来就装着东西），是 52px 给一排 26px 控件留了上下各 13px，对一条工具栏偏松；44 留 9px，仍然舒服，还给正文 8px。这条是全篇价值最低的一条，排在最后做。

A4 / 空态那份稿子的第 4 条 · 形制采纳，内容全换

空屏该能干活，但不该把侧栏抄一遍

它的判断对：一句话加一个大图标，是把一整屏拿去说「这里没东西」。但它填进去的内容，有三分之二是 100px 外就有的东西。

它填了什么，重复在哪

＋ 新建会话就在当前文件夹开一轮

A5 / 引擎的脸那份稿子的第 8 条 · 留内核，换形制

身份留下，永动去掉

「各家引擎该有张脸」这个想法是对的，而且正好长在 omni 的立意上——一个界面接三家，谁在答该有个人格。要换的只有两件事：它一刻不停地蹦，而且蹦在你打字时视线落的那个点上。

它的原案 · 忠实复刻（这排是真在跑的动画）

给 Kimi Code 派个活…
Kimi Code

（上一版我把它们画成飘在空中的了，是我复刻错了——原稿里它们贴着输入框上沿站，脚下各有一颗状态点，正在跑的那只是绿的。摆正之后这个设计其实更成立，批评点也更集中：不是位置歪，是它一直在动。）

.pet svg   { animation: hop 1.8s ease-in-out infinite; }
.pet[…]    { animation: wanderA 8s ease-in-out infinite; }
.pet .eyes { animation: blink 3.6s ease-in-out infinite; }
整段没有 prefers-reduced-motion   （.row__dot--running 和 .meter__fill 都写了）

而这个仓库已经把这件事想清楚过了，status.css 里那段：

/* 一刻不停的加载动画会持续抢注意力；这里是隔一段扫一道：
   600ms 后起第一道，之后每 4s 一道，每道约 1s（占整条时间线的 25%）。
   剩下的时间停在终点，所以看上去就是"扫一下，歇一会儿"。 */

推理微光按这条规矩收着了，吉祥物是三条 infinite。同一个界面里两套关于「动」的标准。

改法：同一件事，换个位置，换个节拍。

  • 位置 —— 挪进 A3 那枚引擎徽章。输入框上沿是你打字时视线停的地方，那里放动的东西成本最高；而「谁在答」本来就该和答案在一根线上。
  • 节拍 —— 静止是常态。只有这一轮真在跑的时候它跳一下，4s 一次、600ms 起、每次约 1s，和 shimmer 逐字对齐。「一轮一跳」不是「一秒三跳」——蹦还是那个蹦，压扁、弹起、砸扁、回弹一个不少，只是频率降到十三分之一，而且它现在有意思了：它在动 = 它在干活。
  • 减少动态效果 —— prefers-reduced-motion 下完全静止，照 .row__dot--running 那条写。

如果你就是想要完整的那一排蹲在输入框上：那是产品性格，是你的决定，不是对错问题。我只要求三件事——闲着的时候停、尊重 prefers-reduced-motion、别放在输入框正上方。三条满足了，随便蹦。

三只原样留着，只改样式

我试着自己重画了一版，画丑了——螃蟹画成了个蜘蛛，两只史莱姆画成了两个素面圆顶，还自作主张多塞了一家 Codex。它那三只本来就是对的：史莱姆就是史莱姆，重画只会画没。

所以这一版一根路径都不动，SVG 逐字沿用它的原案。要改的只有四处样式，下面逐条说。

两边都过，不动。
Claude Code#da7756 · 原值 像素桌宠。白底 3.11、暗底 5.76，
压线过，也不动。

暗底 1.01——整只消失。

改动一 · Grok 在深色模式下是看不见的

这是唯一一处必须动色值的地方，而且是个硬伤不是口味问题：#16161a 正好是 omni --text 的值，压在深色底 #17171a 上，对比度 1.01:1。不是「看不清」，是「不存在」——只剩两只白眼睛浮在黑底上。

原值 · 深色底

#16161a on #17171a · 1.01:1

补一套深色值

#c9c9d2 on #17171a · 10.9:1 
--eng-grok: #16161a;  --eng-grok-eye: #ffffff;
@media (prefers-color-scheme: dark) {
  --eng-grok: #c9c9d2;  --eng-grok-eye: #16161a;   /* 身体和眼睛一起翻 */
}

Kimi 和 Claude 我都算过了，两套底色上都过 3:1（图形的门槛），一个字节不用改。

改动二 · 三条 infinite 收成「一轮一跳」

.pet svg   { animation: hop 1.8s ease-in-out infinite; }
.pet[…]    { animation: wanderA 8s ease-in-out infinite; }
.pet .eyes { animation: blink 3.6s ease-in-out infinite; }
                        ↓
静止是常态。只有这一轮真在跑的时候跳一下，4s 一次、600ms 起、每次约 1s
——和 status.css 那道微光逐字对齐（delay 600 / duration 1000 / interval 4000）

蹦还是那个蹦：压扁蓄力、弹起拉长、落地砸扁、回弹，@keyframes hop 的关键帧一帧不删，只是频率降到十三分之一。这样它还多了个用处——它在动，就是它在干活。

wander（左右溜达 ±7~9px）和 blink 直接删：那两条纯装饰，而且 wander 正好让它们在输入框上方来回扫。

改动三 · 补 prefers-reduced-motion

/* 仓库里 .row__dot--running 和 .meter__fill 都写了这一条，吉祥物那段漏了 */
@media (prefers-reduced-motion: reduce) {
  .pet, .pet svg, .pet .eyes { animation: none; }
}

改动四 · 摆哪儿：两种都行，你挑

我原来主张挪进顶栏徽章。摆正你的原案之后我得说句公道话：贴着输入框上沿站是有道理的——脚下一排状态点也确实好使。真正的毛病是「它一直在动」，那个改动二已经解决了。所以两种摆法都成立：
