P1 · 补丁行高改成整数

1.55 → 20px 机械替换
现状 line-height: 1.55 → 19.375px
方案 line-height: 20px（12.5 × 1.6）

把网格叠上去看。左边每行往下漂 0.625px，第 8 行已经离网格 5px，第 32 行差满一整行； 右边一直咬在格子上。这不是「像素洁癖」——它就是 tokens.css 里 「同一个字，一行清一行糊」那句话描述的东西，只不过那句话当时是写给正文行高的。

判断

P2 · 补丁上语法着色

复用已打包的 lowlight 新增依赖 0
现状 纯文本
方案 按 hunk 分侧扫描后着色

为什么不能逐行高亮。补丁是一行一行给的，而语言不是——这段 hunk 的前半截整个泡在 /** … */ 里。逐行喂给高亮器，块注释会被当成除号加乘号。 正确的做法是按 hunk 分成「旧侧」（上下文 + 删）和「新侧」（上下文 + 增）两段连续文本各扫一遍， 扫描器带着跨行状态走，再把结果按行切回去。这一页里的着色就是这么算的——把上面那段注释的着色和下面代码的着色一起看，它认得出边界。

判断
做。highlight.ts 的 lowlight 实例已经在包里（12 种语言，含 ts/css/json/bash），审核面板复用它一个字节都不增。语言按文件扩展名取，取不到就不染——沿用 highlight.ts 那条「没标语言就不猜」。
动哪儿
highlight.ts 导出一个 highlightLines(lang, lines)；ReviewDiff.tsx 的 UniLine / Side 把 {line.text} 换成 hast 子树；markdown.css 的 .hljs-* 配色原样复用，不另立一套。
风险
大补丁的渲染开销。三道闸门：一次只染当前打开的那一个文件（现在本来就是）、按 hunk 缓存、超过阈值退回纯文本（PatchSkip.large 已有先例）。
验收
ReviewDiff.test.ts 补一例：一段横跨 hunk 边界的块注释，断言不会把注释外的代码染成注释。

P3 · 词级高亮

LCS + 相似度闸门 这一页现算
现状 整行底色
方案 只标真正变了的那几个词

这是 RowEnd.tsx 里一段真实的注释重写。左边你得逐字读两遍中文才敢说「哦，只是把 『不占这一列』改成了『不顶掉时间』、把括号里的话挪了位置」；右边一眼看完。 中文按字分词、英文按词分词——中文没有空格，按词切等于不切。

判断
做，但要有闸门。配对沿用 splitRows 的规则（一段连续的删配一段连续的增，逐行对位）；两行的公共部分不足 30% 时整行不标——那是重写不是改动，全标满等于没标。
动哪儿
新增 review-words.ts（纯函数 + 表驱动测试，和 splitRows 同一待遇）；review.css 加 .rvd__hit；ReviewDiff.tsx 在配对时把两行送进去。
取色
行底 12% 之上再叠 22%（color-mix(--ok 22%, transparent)），合成约 35%。不加粗：等宽字加粗会改变字面密度，一行里几个粗词会把对齐读乱。
风险
LCS 是 O(n·m)。长行按 token 数设上限（超过就整行不标），和上面那条闸门共用一个出口。
限度
配对是逐行对位的（和 splitRows 同一规则）。整段重排、删增行数不等时，会把内容并不对应的两行配到一起——上面右栏第 3、4 行就是这个情况，标出来的比真正改动的多。相似度闸门挡掉最离谱的那类，剩下的挡不住。这是逐行 diff 的通病，不是这条的 bug；要更准得先做行级配对（Patience / Myers），不在本轮。

P5 · hunk 头粘顶

两行 CSS 往下滚看差别
现状 position: static，滚过去就没了
方案 position: sticky; top: 0

两边一起往下滚。右边那条 @@ … export function withAsides(…) 一直贴在顶上—— git 把函数签名塞在 hunk 头尾巴上就是为了这个用途，而现状把它滚走了。 第二个 hunk 顶上来时前一个自然被顶掉，不需要额外的 JS。

判断
做。单栏的 .rvd__line--hunk 和并排的 .rvd__row--full 各加 position: sticky; top: 0; z-index: 1。底色本来就是 --bg-sunken（不透明），不用再补。
动哪儿
review.css:645-649、review.css:689-694。滚动容器是 .rvd，中间没有 overflow 挡着，sticky 直接成立。
附带
粘住时补一条 box-shadow: 0 1px 0 var(--border)——不然它和底下的代码贴成一块，看不出是浮着的。
风险
无。z-index 只在补丁区内部，不与浮层争层级。

P6 · 窄面板：收掉旧行号列，并把「窄了不给并排」那句注释兑现

面板 300px 档 对上 F6 / F7

下面两组都按 300px 面板宽度摆——就是窗口 ≤1280px 时 --workbench-w 的实际值。

现状 单栏 · 两列行号吃掉 90px
方案 单栏 · 按行别只给一个行号
现状 并排 · 任何宽度都能开，每侧剩 14 字符
方案 闸门生效 · 退回单栏，按钮置灰
面板 < 420px：并排不可用
行号
窄容器下单栏只画一个行号，按行别取：删行给旧号、增行给新号、上下文给新号。省 3.6em ≈ 45px，正文多出 6 个字符（+25%）。宽面板下两列照旧——那时候「这行在旧文件的哪儿」是有用的。
并排闸门
.rv 已经是 container-type: inline-size，容器查询直接可用。低于 420px 停用并排（每侧 210px 减去行号与记号，正文约 20 字符，已到下限）：按钮 disabled + data-tip 说明理由，正在并排的自动退回单栏。这就把 ReviewDiff.tsx:18 那句注释兑现了。
动哪儿
ReviewDiff.tsx 的 UniLine（行号按行别取）；review.css 加 @container (max-width: 420px)；Review.tsx 的 split 加一个宽度来源（ResizeObserver 或把闸门放进 Tools）。
风险
闸门要记住用户的选择：窄了自动退回，拉宽了应该自己回到并排，而不是让人再点一次。这条要写进测试。

P8 · 中文在 12.5px 等宽下的落点

要样张，本轮不拍板

--font-mono 链尾已经补过 PingFang SC，「中文兜底到哪个字体」这件事定了。 没定的是字号。这仓库的补丁里中文注释是主体（上面每一段都能看到）， 而 12.5px 的 PingFang SC 比同尺寸拉丁字面密得多。三档摆在一起，请在真机上看，别信这张网页。

12.5px 现值 · --text-code
13px 候选 · 与 --text-sm 同档
判断
本轮不动。但要留一条记录：这个数字从来没有对着「一屏全是中文注释的补丁」看过，而那正是这仓库补丁的常态。
怎么定

如果改

K1

不做补丁正文 font-weight: 450

上一版原型给 .rvd__body 加了 font-weight: 450。450 不是 450。CSS Fonts 4 的权重匹配规则是：目标值落在 400–500 之间时，先向上依次找到 500，再回头往下找。SF Mono 和 PingFang SC 都有 Medium 面，所以 450 会被解析成 500——写 450 只会让人以为存在一档中间量。

这个坑仓库里已经踩过并留了记录：app-main.css:44「550 在 mac 上是半句谎话：PingFang SC 没有 550 面（落到 600）」。同一条推理换个方向而已。

而就算真的要 500：补丁正文加粗会和「增删底色」抢注意力——这一屏上负责说话的是颜色，字重该保持安静。深色下若嫌薄，该调的是 --ink 的透明度档，不是字重。

K2

不做正文抬到 15.5px / 27px

上一版原型把回答正文提到 15.5/27。--text-prose: 15px / --lh-prose: 26px 是核过的，而且 26 取偶数写了理由：奇数行高在 2x 屏上会让相邻两行的字形栅格化结果不一样。27 正好踩上那条。

本方案一个字号都不动——它管的是补丁怎么被读，不是重排字号阶梯。
