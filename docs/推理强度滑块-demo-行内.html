行内条比卡片好在哪、差在哪

好在没有第二个平面。卡片是浮在界面上的一层，行内条就在你眼睛已经在的那一行——改完档位，视线不用回收。

好在那段空地本来就闲着。Kimi Code / 自动审批 / K3 / 最高 靠左、发送键靠右，中间那 300 多 px 一直空着——这条是唯一一个「不占新地方」的方案。

定宽 180，不是「剩多少占多少」。铺满到发送键那一版试过，三个毛病：左边四颗控件读起来像被挤到角落；宽度随模型名长度变（GPT-5.6 Sol 比 K3 宽 60px，条子就短 60px）；6 档摊在 319px 上每档 59px，比它需要的精度宽了一倍多。180px 下每档 32px，够点了。

差在窄窗口下还是得让步：空地不够 180 就用空地，下限 96px。卡片那版是固定 262px，不看窗口脸色。

差在展开这件事本身要动布局。卡片是浮层，弹出来不影响任何人；行内条一长出来，它右边那段空地就得让位——虽然发送键不动（空地在吸收），但每帧的回流是真的。

差在装不下字。「更快 / 更聪明」两个端点标签没地方放，「更快消耗使用额度」也没有——26px 高的一条只放得下条子本身。

「更快消耗使用额度」不占一行了。上一版把它放在档位行下面，一到 ultra 整个输入框长高 18px，把上面的转录区顶走一截——为了说一句话，把你正在读的东西挪了位置。现在它挂在触发器的 title 上，鼠标停一下就有；而「这一档更贵」这句话，紫色和那圈扫光已经说过了。要那行字常驻可见的话，卡片那版有地方放，行内这版没有——这是两版之间一个实打实的取舍。

为什么之前没有卡片圆润 —— 三个原因，全在展开那一下

① 切出来是平口。之前靠 overflow: hidden 收窄，切口是直的——展开过程中它压根不是一枚胶囊，只有到位那一帧才突然圆起来。现在用 clip-path: inset(… round 13px)，切出来的右端自带圆角，全程都是完整的一枚。

② 两套动画在打架。条子原来是 width: 100%，父容器每帧变宽，它自己的宽度也每帧在变，于是拇指位置得用 rAF 每帧重算——外层 320ms、内层 190ms、还有一个每帧覆写，抖就是这么来的。现在条子一开始就是最终宽度（--bw 给定），位置一次算完不再动。

③ 卡片那版动的是 opacity 和 transform——合成层，不碰布局。行内条动的是 width，每帧要整行回流。这一条改不掉（布局确实得让位），但去掉每帧重算之后差距小得多了。

顺带：收起比展开快一档（200ms vs 300ms）——关掉一个东西不需要被欣赏。展开时拇指和填充从最左跟着一起走，看起来是拇指把条子拽开的，不是条子露出来一个静止的拇指。

紫色是 ultra 一家的，普通档走中性灰

从最低档就开始铺紫，等于把「更贵」那句话说了六遍——说六遍就等于没说，真到 ultra 反而没有升级空间了。这条推理这个仓库写过两次：status.css 说「一刻不停的动画会持续抢注意力」，tokens.css 的用量表那段说「一直是彩色的话，真到危险区就没有升级空间了」。

而且引擎不报 ultra 的话，这套紫色从头到尾都不出现。换成 K2.7 试一下：它报三档，条子推到头也还是灰的——不是「灰色版的 ultra」，是这个模型根本没有那一档。

它凭什么这么响

理由是：ultra 是这一行里唯一一个会明显改变花销的开关。ModelPicker.tsx 的 EFFORT 表里，六档只有它带说明，原文就是「更快消耗使用额度」——那行字是抄的，不是我编的。它不是「再强一点」，是「这一轮开始烧钱了」。

那道慢绕的高光不是庆祝动画，是常驻提示：你要是忘了自己开着这一档，这一圈会一直提醒。prefers-reduced-motion 下高光和星点闪烁都不出现，颜色、渐变、柔光留着——降级之后信息不丢。

还有一条要你拍板：tokens.css 开头写着「强调色只用于焦点与链接；主按钮用近黑，不用彩色」。这根紫条是这套界面里第一处大面积的、非内容语义的颜色。我认为它值——它标的是花钱；但它确实是对那条规矩开的第一个口子，得是有意开的。
