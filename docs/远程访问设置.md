# 远程访问：从手机上看住并放行本机的 agent

> 面向使用者与 dev。**这份是照着做的操作手册**，设计与取舍见
> [`手机端远程方案.md`](手机端远程方案.md)。
>
> 文中每一条命令都在 2026-08-17 真跑过；`your-proxy.your-tailnet.ts.net`
> 是这台机器上实际配好的那条路，换服务器时把它换掉。

---

## 0. 一分钟看懂这条路

```
手机浏览器
   │ https（真证书）
   ▼
kr（中转服务器）
   │ tailscale serve :8443 → 127.0.0.1:17800
   ▼
127.0.0.1:17800  ← ssh -R 反向隧道 ← 你的 Mac
   │
Switchback 主进程（只 listen 127.0.0.1:17800）
   │
引擎进程 + 你的仓库
```

四件事各归各：

| 谁 | 管什么 |
| --- | --- |
| Switchback 主进程 | 服务端本身。**只听回环，没有绑公网的开关。** |
| `ssh -R` | 把那个回环口送到 kr 的回环上。中转机器上**一行代码都不用跑**。 |
| `tailscale serve` | TLS 终止 + 真证书。**只在你自己的 tailnet 里可见**，公网扫不到。 |
| 设备令牌 | 「你是谁」。配对码换来，可单台吊销。 |

---

## 1. 在 Switchback 里打开（一次）

**设置 → 远程访问 → 打开**。默认端口 17800，默认档位上限「自动审批」。

「隧道那头的域名」填：

```
your-proxy.your-tailnet.ts.net:8443
```

**这一栏不填就只认回环**，从隧道进来的请求会全部 403——那是 `Host` 闸在挡
DNS 改绑（见 `main/remote/fence.ts`），不是配置坏了。

---

## 2. 起隧道

**交给 launchd 常驻**（开机自启、断了 15 秒内自己拉起）：

```sh
scripts/tunnel.sh install     # 装上并起来（会先停掉手动起的那条）
scripts/tunnel.sh status      # 看：托管没有、在不在跑、转了哪几个口
scripts/tunnel.sh uninstall   # 撤掉
```

日志在 `~/Library/Logs/switchback-tunnel.log`，每次起、每次断都记一行。
不想常驻的话 `start` / `stop` 照旧是手动起停一条（托管着时起停的是 launchd 那份）。

它跑的就是这一条，没有藏东西：

```sh
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
    -R 127.0.0.1:17800:127.0.0.1:17800 kr-omni
```

`ExitOnForwardFailure=yes` 是要紧的一条：端口被占时**当场退出**，而不是留下
一条 ssh 通了、转发没成的连接——那种连接看起来是好的，直到你在手机上打不开。
launchd 守着的时候，「当场退出」之后它会再试；而 kr 那头要能及时放开死掉的旧会话占着的端口，
见 §5 的 `ClientAliveInterval`。

### 顺带转别的口（比如 remote-bash）

本机别的远程服务不用再各开一条隧道、各配一把钥匙。`SWITCHBACK_TUNNEL_EXTRA` 写几段
`远端口:本机地址:本机口`，`install` 时写进 launchd 那份 plist：

```sh
# remote-bash（rbd）只听本机的 Tailscale 地址，所以本机地址写那个（tailscale ip -4）
SWITCHBACK_TUNNEL_EXTRA="7681:<本机 Tailscale 地址>:7681" scripts/tunnel.sh install
```

另外两处要跟着配：受限钥匙那一行多放行这个远端口（§4），kr 上给它挂一个 serve 端口（§5）。
之后 remote-bash 从 `https://your-proxy.your-tailnet.ts.net:8444/?token=…` 打开
（`sh scripts/rbd-service.sh url` 打印的那条，把前面的 `http://<Tailscale 地址>:7681` 换掉）。
它不查 `Host`，套上中转不用改它的代码。

## 3. 在手机上打开

1. 手机上把 **Tailscale 打开**（手机要先加入同一个 tailnet）。
2. Safari 打开 `https://your-proxy.your-tailnet.ts.net:8443/`
3. 桌面上「设置 → 远程访问 → 配对新设备」，把那**八位码**输进手机。
4. 配好之后**加到主屏**（分享 → 添加到主屏幕）。这一步在 iPhone 上是必需的，
   不是锦上添花：**Safari 标签页里的 PWA 收不到推送**。
5. 加到主屏之后打开它，在列表底下点一次「跑完了叫我一声」。

配对码五分钟有效、**用一次作废**、错十次锁一分钟。

## 3.5 在另一台电脑上用完整界面

手机端是「看住与放行」；另一台电脑要的是**这台上的完整界面**（换模型、接力、审核面板……），
走同一条隧道、同一个域名，只是地址后面加 `/desk/`：

1. 那台电脑上把 **Tailscale 打开**（或者别的能到中转服务器的路）。
2. 浏览器打开 `https://your-proxy.your-tailnet.ts.net:8443/desk/`。**那台电脑的 Tailscale 要开着
   「使用 Tailscale DNS」**（菜单里的 Use Tailscale DNS settings），否则 `*.ts.net` 的名字解析不了——
   证书是签给这个名字的，换成 IP 也打不开
3. 这台上「设置 → 远程访问 → **配对电脑**」，把八位码输进那台电脑的配对屏。
   **要按「配对电脑」开码**：按手机开的码配上来只能看住与放行，配对屏会提示你重配。
4. 标签页标题写着 `Switchback · <这台的主机名>`——两台各开一个窗口时，靠它分清在哪台上点「允许」。

每台设备的档位上限可以在「已配对的设备」里单独改；电脑能调的宿主通道是一张白名单
（见 [`远程模式方案.md`](远程模式方案.md) §2.2），装引擎、自更新、远程访问这几件只能在这台上做。

## 4. 密钥：这把钥匙能做什么，以及怎么换

隧道用的是**一把专用密钥**（`~/.ssh/omni-tunnel`），不是你的主密钥。
服务器上它长这样：

```
restrict,port-forwarding,permitopen="127.0.0.1:1",command="/bin/false",permitlisten="127.0.0.1:17800",permitlisten="127.0.0.1:7681" ssh-ed25519 AAAA…
```

（后面那条 `permitlisten` 是给 §2 里顺带转的 remote-bash 的；没转别的口就只有 17800 那一条。
`scripts/tunnel.sh rotate` 换钥匙时按 `SWITCHBACK_TUNNEL_EXTRA` 把它们全写上——**在同样的环境下跑**，
漏一个，那个口在新钥匙上就开不出来。）

逐条的意思：

| 片段 | 挡住什么 |
| --- | --- |
| `restrict` | pty、agent 转发、X11、user-rc、**以及全部端口转发** |
| `port-forwarding` | 把转发开回来——**注意它开回来的是本地和反向两样** |
| `permitopen="127.0.0.1:1"` | 把**本地转发**（`-L`）钉死在一个永远连不通的目标上，等于全禁 |
| `command="/bin/false"` | **连一条命令都跑不了**。`restrict` 不管命令执行——少了这条，泄漏出去的钥匙照样能 `ssh kr-omni 'cat /etc/shadow'` |
| `permitlisten="127.0.0.1:17800"`（及后面几条） | 只能开列出来的这几个反向端口，且必须绑回环 |

所以这把钥匙泄漏的最坏后果是**有人能占用 kr 上的那个端口**，不是拿到你的服务器。

> **`permitopen` 这一行是后补的，原来漏了，而漏掉的后果比看上去严重。**
> `permitlisten` 只管反向那一半，`port-forwarding` 却把本地那一半也开着——
> 实测拿这把「受限」钥匙跑 `ssh -L 19998:127.0.0.1:22 <用户>@kr`，
> 当场读到了 sshd 的版本横幅（`SSH-2.0-OpenSSH_…`）。也就是说它能把 kr 当成**任意 TCP 代理**：
> 内网的任何服务、云厂商的元数据地址，都在射程内。上面那句「不是拿到你的服务器」
> 在补这一条之前是**假的**。补上之后同一条命令什么都读不到。
>
> 值必须写成 `host:port`。**写 `none` 会把整行搞废**——那个写法只在 sshd_config 的
> `PermitOpen` 里有效，authorized_keys 的 `permitopen` 解析不出端口就把整行判成无效，
> 表现是这把钥匙连认证都过不去（`Permission denied (publickey)`），
> 而不是「转发被拒」。这条也是实测踩出来的。

### 换密钥

```sh
scripts/tunnel.sh rotate
```

**一条就够，不用再手动重启隧道**——它跑完时新钥匙已经在带着隧道跑了。

五步，每一步都打印出来：

1. 生成新钥匙（注释里带时间戳，同一天换两次也不会撞）
2. 用**你的主密钥**登进 kr，先备份 `authorized_keys`，再把新公钥**追加**上去
   （受限的那把跑不了命令，换不了自己）
3. 停掉旧隧道，**用新钥匙起一条真的**——`permitlisten` 只许那一个端口，
   所以这一步验的就是真实那条路，不是「ssh 能连上」而已
4. 新的确认能用之后，才把旧的从服务器上删掉
5. 换掉本机 `~/.ssh/omni-tunnel`

**顺序是「装上新的 → 验它真的能用 → 才删旧的」。** 中间任何一步失败，
旧钥匙都还在服务器上，`scripts/tunnel.sh start` 就回到原样了——
这是一次动别人服务器的操作，失败的代价是「人在外面、门开不了」。
服务器上会留一份 `~/.ssh/authorized_keys.bak-<时间戳>`，确认没问题之后自己清掉。

换完想自己验一遍这把钥匙的边界（两条都该失败）：

```sh
ssh -i ~/.ssh/omni-tunnel -o IdentitiesOnly=yes <用户>@<kr的IP> id            # 什么都不输出：命令没跑
ssh -i ~/.ssh/omni-tunnel -o IdentitiesOnly=yes -o ExitOnForwardFailure=yes \
    -N -R 127.0.0.1:19999:127.0.0.1:19999 <用户>@<kr的IP>                     # remote port forwarding failed
```

### 丢了手机

**设置 → 远程访问 → 已配对的设备 → 吊销**。它**正连着的那条连接会当场断开**，之后也连不上了。
吊销是可逆的（重新配一次就回来），所以没有二次确认——需要它的那一刻你不会有耐心。

## 5. 中转服务器上配了什么（kr）

只有三样，都可撤销：

```sh
# 1. authorized_keys 里那一行受限公钥（见上）
# 2. tailscale serve：Switchback 在 8443，顺带转的 remote-bash 在 8444
tailscale serve --bg --https=8443 http://127.0.0.1:17800
tailscale serve --bg --https=8444 http://127.0.0.1:7681
tailscale serve status            # 看
tailscale serve --https=8444 off  # 撤
# 3. sshd 的一个 drop-in：死掉的隧道会话 90 秒内放手
cat /etc/ssh/sshd_config.d/50-switchback-tunnel.conf   # ClientAliveInterval 30 / ClientAliveCountMax 3
```

第三样是 launchd 常驻之后才必需的：Mac 睡一觉、换一次网，旧的那条 ssh 没机会说再见，
kr 默认要等 TCP keepalive（7200 秒）才认定它死了、放开它占着的反向端口——那两个小时里
自动重连上来的新隧道一律「remote port forwarding failed」。ClientAlive 只会断掉**不应答**的连接，
正常的 ssh 客户端都会自动回应，不影响别的会话。改完先 `sshd -t` 再 `systemctl reload ssh`。

**没有装 node、没有起任何服务、没有改 nginx。**

### 为什么不用 443

那台机器的 `*:443` 已经被别的服务占着。
80 是空的，但那条路要域名 + Let's Encrypt，而 `tailscale serve` 直接给一张
真证书，省掉整条证书链的维护。

### 要公网可达（不想开 Tailscale）怎么办

一条命令：

```sh
tailscale funnel --bg --https=8443 http://127.0.0.1:17800
```

**但先想清楚代价**：这会把这个入口暴露到公网，届时挡在前面的只有设备令牌
（256 位随机数）和 `Host` 闸。而它后面是一台能执行任意命令的机器。
默认没有开它，是有意的。

## 6. 出问题时按这个顺序查

| 现象 | 先看哪儿 |
| --- | --- |
| 手机上打不开页面 | `scripts/tunnel.sh status`；再 `ssh kr 'curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:17800/'` |
| 页面开得了，一直「正在连接…」 | Tailscale 开了吗；`tailscale serve status` 还在吗 |
| 全是 403 | 「隧道那头的域名」那一栏填了吗、和地址栏里的**完全一致**吗（含端口） |
| 页面 404 但 API 通 | 前端没构建：`pnpm build:web` |
| 401 / 一直回配对屏 | 令牌被吊销了，或者换了机器。重新配一次 |
| 收不到推送 | 加到主屏了吗（iPhone 必需）；点过那颗按钮吗；`~/Library/Application Support/Switchback/remote-devices.json` 里那台设备有没有 `push` 字段 |
| 端口被占，隧道起不来 | `ssh kr 'ss -tlnp \| grep 17800'` |
| 隧道日志一直「remote port forwarding failed」 | kr 上还挂着死掉的旧会话：§5 那个 drop-in 在不在（`sshd -T \| grep clientalive`），在的话 90 秒内会自己好 |
| 电脑上打不开，`Could not resolve host` | 那台的 Tailscale 没开「使用 Tailscale DNS」，`*.ts.net` 解析不了 |
| 远程连得上但很卡 | 那台去 kr 走的是不是 DERP：`tailscale ping <kr 的名字>`，见 via 后面是 `DERP(…)` 还是 IP。是 DERP 的话，kr 云厂商防火墙放行入站 UDP 41641 |

不带 Electron 单独调浏览器端：

```sh
pnpm build:web
pnpm harness:web            # 合成数据，不起引擎
node scripts/shot-web.mjs   # 出图（手机/桌面各一张）
```

## 7. 已知限制

- **Switchback 得开着。** 服务端住在 Electron 主进程里，退出应用远程就断。
  codex 那套跑在独立守护进程里，Switchback 还没有。
- **Mac 会睡。** 有活在跑的时候 Switchback 会挡住**空闲休眠**（远程开着才挡，
  免得平时把电池管理关掉），但它**挡不住盖盖子**——那条路由 macOS 的 clamshell
  逻辑管，接了电源和外部显示器才不睡。也挡不住手动选「睡眠」。
  要真的不睡：接电源、别盖盖子，或者 `caffeinate -s`。
- **推送要手动开一次**，而且 iPhone 上必须先加到主屏。权限只问一次——
  拒了之后浏览器不会再问，只能去系统设置里改。
- **久没碰的会话正文会晚一拍。** 全量重建只带最近几条的正文（4000 条事件的预算），
  其余只发头；打开那一条时才去读磁盘补。表现是先看到标题和空白，几百毫秒后正文到。
- **中转看得见明文。** 服务器是你自己的，v1 接受这一点。
