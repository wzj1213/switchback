# 远程访问：从手机上看住并放行本机的 agent

> 面向使用者与 dev。**这份是照着做的操作手册**，设计与取舍见
> [`手机端远程方案.md`](手机端远程方案.md)。
>
> 文中每一条命令都在 2026-08-17 真跑过；`your-proxy.your-tailnet.ts.net`
> 是这台机器上实际配好的那条路，换服务器时把它换掉。

---

## 0. 一分钟看懂这条路

```
手机浏览器
   │ https（真证书）
   ▼
kr（中转服务器）
   │ tailscale serve :8443 → 127.0.0.1:17800
   ▼
127.0.0.1:17800  ← ssh -R 反向隧道 ← 你的 Mac
   │
omni 主进程（只 listen 127.0.0.1:17800）
   │
引擎进程 + 你的仓库
```

四件事各归各：

| 谁 | 管什么 |
| --- | --- |
| omni 主进程 | 服务端本身。**只听回环，没有绑公网的开关。** |
| `ssh -R` | 把那个回环口送到 kr 的回环上。中转机器上**一行代码都不用跑**。 |
| `tailscale serve` | TLS 终止 + 真证书。**只在你自己的 tailnet 里可见**，公网扫不到。 |
| 设备令牌 | 「你是谁」。配对码换来，可单台吊销。 |

---

## 1. 在 omni 里打开（一次）

**设置 → 远程访问 → 打开**。默认端口 17800，默认档位上限「自动编辑」。

「隧道那头的域名」填：

```
your-proxy.your-tailnet.ts.net:8443
```

**这一栏不填就只认回环**，从隧道进来的请求会全部 403——那是 `Host` 闸在挡
DNS 改绑（见 `main/remote/fence.ts`），不是配置坏了。

---

## 2. 起隧道

```sh
scripts/tunnel.sh start     # 起
scripts/tunnel.sh status    # 看
scripts/tunnel.sh stop      # 停
```

它跑的就是这一条，没有藏东西：

```sh
ssh -f -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 \
    -R 127.0.0.1:17800:127.0.0.1:17800 kr-omni
```

`ExitOnForwardFailure=yes` 是要紧的一条：端口被占时**当场退出**，而不是留下
一条 ssh 通了、转发没成的连接——那种连接看起来是好的，直到你在手机上打不开。

---

## 3. 在手机上打开

1. 手机上把 **Tailscale 打开**（手机要先加入同一个 tailnet）。
2. Safari 打开 `https://your-proxy.your-tailnet.ts.net:8443/`
3. 桌面上「设置 → 远程访问 → 配对新设备」，把那**八位码**输进手机。
4. 配好之后**加到主屏**（分享 → 添加到主屏幕）：那样它按应用的样子跑，
   没有地址栏，将来的推送也只有这种形态收得到。

配对码五分钟有效、**用一次作废**、错十次锁一分钟。

---

## 4. 密钥：这把钥匙能做什么，以及怎么换

隧道用的是**一把专用密钥**（`~/.ssh/omni-tunnel`），不是你的主密钥。
服务器上它长这样：

```
restrict,port-forwarding,command="/bin/false",permitlisten="127.0.0.1:17800" ssh-ed25519 AAAA…
```

逐条的意思：

| 片段 | 挡住什么 |
| --- | --- |
| `restrict` | pty、agent 转发、X11、user-rc、**以及全部端口转发** |
| `port-forwarding` | 把转发单独开回来（只有这一样） |
| `command="/bin/false"` | **连一条命令都跑不了**。`restrict` 不管命令执行——少了这条，泄漏出去的钥匙照样能 `ssh kr-omni 'cat /etc/shadow'` |
| `permitlisten="127.0.0.1:17800"` | 只能开这一个反向端口，且必须绑回环 |

所以这把钥匙泄漏的最坏后果是**有人能占用 kr 上的那个端口**，不是拿到你的服务器。

### 换密钥

```sh
scripts/tunnel.sh rotate
scripts/tunnel.sh stop && scripts/tunnel.sh start
```

它做三件事：生成新钥匙 → 用**你的主密钥**登进 kr 把公钥换掉（受限的那把跑不了命令，
换不了自己）→ 本地替换。顺序是「先装新的再删旧的」，反了会在中间那一刻把自己关在门外。

手动做的话：

```sh
ssh-keygen -t ed25519 -N '' -C "omni-tunnel-$(date +%Y%m%d)" -f ~/.ssh/omni-tunnel.new
ssh kr "grep -v omni-tunnel ~/.ssh/authorized_keys > /tmp/ak && mv /tmp/ak ~/.ssh/authorized_keys &&
        echo 'restrict,port-forwarding,command=\"/bin/false\",permitlisten=\"127.0.0.1:17800\" $(cat ~/.ssh/omni-tunnel.new.pub)' >> ~/.ssh/authorized_keys"
mv ~/.ssh/omni-tunnel.new ~/.ssh/omni-tunnel && mv ~/.ssh/omni-tunnel.new.pub ~/.ssh/omni-tunnel.pub
```

### 丢了手机

**设置 → 远程访问 → 已配对的设备 → 吊销**。那台设备下一次连接立刻失效。
吊销是可逆的（重新配一次就回来），所以没有二次确认——需要它的那一刻你不会有耐心。

## 5. 中转服务器上配了什么（kr）

只有两样，都可撤销：

```sh
# 1. authorized_keys 里那一行受限公钥（见上）
# 2. tailscale serve
tailscale serve --bg --https=8443 http://127.0.0.1:17800
tailscale serve status          # 看
tailscale serve --https=8443 off  # 撤
```

**没有装 node、没有起任何服务、没有改 nginx。**

### 为什么不用 443

那台机器的 `*:443` 已经被别的服务占着。
80 是空的，但那条路要域名 + Let's Encrypt，而 `tailscale serve` 直接给一张
真证书，省掉整条证书链的维护。

### 要公网可达（不想开 Tailscale）怎么办

一条命令：

```sh
tailscale funnel --bg --https=8443 http://127.0.0.1:17800
```

**但先想清楚代价**：这会把这个入口暴露到公网，届时挡在前面的只有设备令牌
（256 位随机数）和 `Host` 闸。而它后面是一台能执行任意命令的机器。
默认没有开它，是有意的。

## 6. 出问题时按这个顺序查

| 现象 | 先看哪儿 |
| --- | --- |
| 手机上打不开页面 | `scripts/tunnel.sh status`；再 `ssh kr 'curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:17800/'` |
| 页面开得了，一直「正在连接…」 | Tailscale 开了吗；`tailscale serve status` 还在吗 |
| 全是 403 | 「隧道那头的域名」那一栏填了吗、和地址栏里的**完全一致**吗（含端口） |
| 页面 404 但 API 通 | 前端没构建：`pnpm build:web` |
| 401 / 一直回配对屏 | 令牌被吊销了，或者换了机器。重新配一次 |
| 端口被占，隧道起不来 | `ssh kr 'ss -tlnp \| grep 17800'` |

不带 Electron 单独调浏览器端：

```sh
pnpm build:web
pnpm harness:web            # 合成数据，不起引擎
node scripts/shot-web.mjs   # 出图（手机/桌面各一张）
```

## 7. 已知限制

- **omni 得开着。** 服务端住在 Electron 主进程里，退出应用远程就断。
  codex 那套跑在独立守护进程里，omni 还没有。
- **Mac 会睡。** 盖上盖子就断，接电源 + `caffeinate -s` 能挡一部分。这条修不干净。
- **还没有推送。** 现在要自己想起来去看手机。`main/attention.ts` 的出口已经收在
  一个 `tell()` 上，接 Web Push 是下一步。
- **全量重建是整份发的**（所有会话的完整历史）。会话多了之后蜂窝网上会慢。
  分级 replay 的通道（`watch` 帧）已经铺好，还没接。
- **中转看得见明文。** 服务器是你自己的，v1 接受这一点。
