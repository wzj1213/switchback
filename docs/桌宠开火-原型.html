史莱姆 ← 静默。走得慢、量大，零输出越久来得越勤。
蜂群 ← 限流。血薄但一来一簇、飞在半空、走得快。低流速时最难清——不是因为它们厚，是因为你的射速跟不上它们的只数，那正是限流的体感。
胖子 ← 上下文逼近上限。血厚走得极慢，而且一路把纸带上的字吃掉。这一条是三种里最准的：上下文满了，前面产出的东西真的会被压缩掉。
子 agent · 放出去的悬浮炮台
不做成小桌宠，做成主桌宠放出去的装备。理由是硬的：桌宠编码的是「哪一家引擎」（五只＝五家，压暗＝不是当前这家）。把子 agent 画成小一号的桌宠，读出来是「又来了几个小引擎」——而子 agent 恰恰不是另一家引擎，它是同一个 agent 伸出去的手。
形是磁悬浮小炮：一颗圆核心 + 一截短炮口，底下一圈 accent 磁环——本体和磁环之间那道缝就是「悬浮」本身，缝里两点场弧跟着脉动一起呼吸，中间那颗芯读作「通着电」。
三条把「是装备不是角色」钉死：没有眼睛（有眼睛的是角色，没眼睛的是机器）· 配色跟枪走不跟身体走（所以它和主桌宠手里那把枪是一套，和桌宠本身不是）· 绕着本体转，不是往前铺一排（靠得近＝属于它；铺一排会读成「一行东西」，还跟纸带和计划旗抢地方）。
前后遮挡是假的：椭圆下半圈算「近」（原大、不透明），上半圈算「远」（缩到 0.82、压到五成透明）。canvas 在桌宠 DOM 之上、画不到它背后去，但把远的那半圈压暗一档，眼睛会自己把它读成绕到后面去了。
关键在于主桌宠这时候自己不开火——产出还在，只是不是它在打。现在的界面里，「主 agent 在等三个子 agent」和「主 agent 卡住了」长得一模一样，而前者恰恰是干得最欢的时候。
流速在几只之间平分：三只同时打，每只的射速就是三分之一。这条也不是装饰——它就是 fan-out 的真实代价。
经验 · 就是累计 token，0–100 级
不再有别的加分项，连折算这一步都省了：等级是「累计 token」的一个单调函数，顶栏那个 累计 和桌宠的等级说的是同一件事的两种写法。每只桌宠一份，跨会话累计。于是「Kimi 47 级、Claude 12 级」直读作你实际用哪家用得多——它是使用分布，不是成就系统。

曲线定在 31600 × lv^3.25，满级 100B。上一版定的是 190M，理由是「顶栏那个 198555k 正好落在满级线上」——那是错的，错在锚点：usage.ts 里 totalTokens 的注释写着「本会话累计」，198M 是一次会话烧掉的量，不是这个项目终身的量。按那条曲线，开一次长会话就直接满级，等级从第二天起就是个常数——而一个永远显示 100 的等级和不显示是一回事。
重定之后：Lv5 = 6M（头一个小时）· Lv15 = 210M（一次大会话，顶栏那个数现在落在 Lv14，正好差一级要升）· Lv35 = 3.3B（两三周）· Lv65 = 24.6B（几个月）· Lv100 = 100B（约五百次大会话，一年半的重度日用）。
这条曲线的形状本身就是一句话：头一天你就能看见它在长，而后面是留给真的把这家引擎用穿了的人的。

没有上限。先前在 100 级封了顶，那是错的，而且错得比数字大小更根本——等级就是「累计 token」的另一种写法，一封顶它就不再是那个数的函数了，而那正是这套设计唯一的立足点。封顶之后界面开始撒谎：数字还在涨，等级不动了。何况会撞到顶的恰恰是把这家引擎用得最狠的那批人，凭什么是他们先没得看。
token 每翻一倍等级 ×1.24：Lv100=100B · Lv123=200B · Lv203=1T · Lv412=10T · Lv1701=1000T。它会一直慢慢走，不会停。
美术是有限的，数字不是——这两件事分开处理：枪的形制五档，最后一档 Lv65 到顶；再往上换刻痕，Lv65 之后每 20 级在机匣上多刻一道，画到八道封顶。画面到此为止，而数字永远精确，标签里写的一直是真值。
装备 · 五档形制，逐档焊零件

出场

开应用、或者切引擎的时候，那只不是「啪」地出现，是登场。每家按自己的物性来——这一层比配色更能说清「换了一家」。出场没结束不出列、不抽枪：登场是一拍，干活是下一拍。

播放出场动画 关掉之后切引擎是直接换人。系统「减少动效」开着时这一项自动失效，不用你来关。
看一眼 史莱姆砸下来，落地摊成一滩再弹回原形——软体没有别的出场方式。螃蟹是降落伞空投的（蟹不会飞），落地那刻伞脱钩飘走。鲸先炸一圈水花再划弧跃出来，溅一地水点。未接入那只只是淡进来：照 pets.css 里那句「没见过的那一家不编花样」，它连出场都不该有花样，这本身是个信号。

僵尸

左边会爬过来的那些。它们不是随机刷出来的关卡内容，是压力的化身：上下文越满、静默越久来得越勤，而火力恒等于流速——没有输出就没有子弹，那时候它们会走到跟前。

密度 「常」是八到十五秒一只；压力大时最短会缩到一秒多一只。关掉之后瞄准那套也就没有目标了——枪会一直端平。
种类 史莱姆←静默 · 蜂群←限流（血薄但一来一簇，低流速时最难清）· 胖子←上下文逼近上限（一路把纸带上的字吃掉）。「混合」按当时的压力源自己挑。

这一套的边界

火力恒等于流速。等级、装备、皮肤一律不改射速、不改伤害、不改任何一个能影响「打不打得掉」的数——一旦等级能改火力，画面上的胜负说的就是你的存档，而不是引擎此刻的表现。
唯一有资格影响命中率的是上下文：靶上被它吃掉的那圈不算命中，因为上下文变满本来就是真实的能力衰减，不是存档进度。
经验就是累计 token，每只一份、跨会话累计，所以「Kimi 47 级、Claude 12 级」直读作你实际用哪家用得多——它是使用分布，不是成就系统。

先说一件会决定对错的事：这个窗口里有两个时钟

上下文环、累计、缓存三个数都来自 Usage（packages/protocol/src/event.ts:14），而 Usage 每一轮结账时才回来一次——它是一道阶梯，中间那几分钟是空的。
每一帧都能拿到的只有 item.delta.append 的字节流（event.ts:125）。所以「流速」只能按字节估：中文约 0.7 token/字，英文约 0.27 token/字符。
两条推论，六个方案都得守：一、界面上写 ~142 t/s 的波浪号，或者干脆写「字/秒」——这个窗口里已经有三个是结算过的数字了，别把估出来的那个摆成同一种脸。二、任何「流速平滑地把环推涨」的画法都是假的，环只会在结账那一下跳。真正连接两者的量叫在途：吐出来了、还没结账的那一批。

另：演示里结账的步进放大了 8 倍，否则一轮两三千 token 在 1049k 的环上挪不动一个像素。上下文涨到 97% 会自动回到 53%，好让你看全 灰 → 黄 → 红 三档。

结论一（第一批）：位置你挑对了，形式挑错了

桌宠那一片确实是对的地方。九分钟的等待里，眼睛就停在输入框上沿那一带，桌宠是全窗口唯一在动的东西。信号该放在视线已经落着的地方。

但「射击」是错的音量。一秒十几发，头一个小时很爽，第三天你会自己去设置里关掉它——而一个默认会被关掉的默认值，就是选错了。

右侧那条是对的音量、错的地方。安静、有历史、能回答「刚才那半小时是不是被限流了」——但右边缘是等待时眼睛最不会去的地方，它擅长「你去查」，不擅长「它来告诉你」；而且要真花掉 44px 宽度，这个窗口的横向已经不宽裕。

C 默认给「地面波形」。输入框上沿那条 1px 的边——桌宠站的那条地面——变成波形，桌宠踩着浪起伏。零新增控件、零新增宽度、静止时它就是那条本来就在的边框；而「平 / 慢呼吸 / 虚线 / 起伏」四个状态一眼分得开，正在思考 9m 30s 那个秒表一个都分不出来。附带的好处是：pets.css 里已经写下的那句「它在动 = 它在干活」，第一次有了真的数据依据，桌宠不再只是装饰。

E 顺手把顶栏尾巴一起做了。半小时的工作量，顶栏那一行本来就是放数字的地方，要精确值的时候有个地方看。

A 桌宠开火留成开关。设置里一句「桌宠开火」，默认关。它值得存在——限流到 15 t/s 时你能一颗一颗数出子弹，那种「变慢了」的体感是任何数字都给不了的。

B 等到真有人问「刚才是不是被限流了」再说。那时候要的是一条时间轴，不是此刻的数。

D 在途弧是唯一诚实处理两个时钟的画法，但 12px 装不下它想说的话。把它的内容写进环的悬停卡里就够了：上下文 560k / 1049k · 53%｜在途 ~1.2k 未结账｜~142 t/s。

结论二（第二批）：换个编码，比换个位置值钱

第一批六个方案，本质上是同一件东西摆在六个位置。第二批不是——它们编码的根本不是同一个量：G 编码速度、H 编码在途、I 编码这一轮的形状、J 编码钱、K 编码存活、L 编码产出量。问「放哪儿」之前，先想清楚要说的是哪一个。

K 如果只做一件事，做这个。pets.css 里给已经存在的那颗 6px 绿点加一条按流速驱动的 scale/opacity，别的一个字不用改——这是全场改动量最小的一个，而它把「它是不是还活着」这个九分钟等待里唯一真正要紧的问题答满了。「一下一下＝慢、常亮＝快」这个读法不用教，所有人看硬盘灯都已经会了。

I 如果只做一件「有内容」的，做这个。它替换的 正在思考 9m 30s 是全窗口最没用的一行——一个不透明的秒表。拆成本轮时间轴之后，同一行告诉你这九分钟到底花在哪。而且它是十二个里唯一能一眼看出「卡住」的（黄色那一段有宽度，赖不掉）。

J 顺手做。它是唯一说「你在花钱」的那个，几乎零成本。它滚的那一位是估出来的，结账时 Usage 回来会把它拨正一下——那个「自我纠正」不要藏起来，它是这套双时钟数据唯一诚实的呈现方式。

G 值得和 C 做个 A/B。C 把速度编码成波的振幅和频率，那是要「看」的；G 编码成质地的速度，那是余光就能读的——人眼判断「东西移动得多快」比判断「波多高」快得多。真做的话记住那个坑：地面必须是随机点阵，等距花纹跑快了会出现车轮效应，看起来反而变慢。

H 和 A 一组，做成同一个「桌宠戏法」开关。它是最讨喜的一个，也是最玩具的一个；但「东西吃进去了、还在肚子里、还没算账」这件事不需要任何说明文字，它比 D 那道 12px 的弧把「在途」讲得清楚得多。

L 留着。横轴按 token 而不是时间，这个视角是对的，但它太像游标卡尺了。等到真有人问「这一轮到底出了多少」再说。

所以我最后会做的是这套

三个几乎白送的，全做，互不重叠：
K 头顶那颗点跳 → 回答「还活着吗」　·　I 秒表拆成时间轴 → 回答「这九分钟在干嘛」　·　J 累计位滚字 → 回答「花了多少」

速度感那一层，C 和 G 里挑一个（我押 G，但值得实测）。输入框上沿那条边只有一条，C／G／L 三个本来就该是同一个组件的三种皮。

A ＋ H 打包成设置里一句「桌宠戏法」，默认关。它们的价值是第一天的惊喜和长期的陪伴感，不是信息密度——别拿它当默认。

B 和 D 先不做。B 要等到有人问「刚才那半小时是不是被限流了」；D 的内容塞进环的悬停卡就够了。

最后一句，可能比上面全部都重要

这十二个方案有一个共同的前提：你正看着这个窗口。而九分钟的等待里，真实情况是你早就切走了——去看文档、去看另一个项目、去泡咖啡。
那么真正的缺口不在窗口里，在窗口外：Dock 角标（跑着 / 卡住 / 要审批）、系统通知（这一轮结束了、卡住超过 N 分钟了）、菜单栏那颗小点。窗口内这十二个解决的是「你在看着」的那一半；而另一半才是九分钟真正发生的地方。

出场　pets.css 里加几条 keyframes 是不够的——伞和水花在 DOM 里根本没有对应元素。所以出场横跨两层：身体的位移与拉伸走 petPaint.ts 已有的 transform 通道，伞绳、水点、落地那圈尘走开火那张 canvas。四种登场按物性分：软体只能砸下来（落地摊成一滩再弹回），蟹不会飞所以是伞投的（落地那刻伞脱钩），鲸先炸一圈水花再划弧跃出，没见过的那一家淡进来——照 pets.css 那句「不编花样」，它连出场都不该有花样。出场没结束不出列、不抽枪：登场是一拍，干活是下一拍，两拍搅在一起就都看不清。
渲染　四条都做了：每帧只读一次布局（fit() 把 rect 挂回元素，handOf() 直接拿，原来一帧要付四次强制样式计算）；僵尸精灵烘到离屏 canvas（被咬的缺口是 destination-out，围攻档十只就是十次合成，而画的是同一张图——现在只剩十次 drawImage，缓存键带主题代数）；字体串与枪的三档混色一帧只算一次（mix() 要解析十六进制，十五块逐块算等于一帧解析四十五次）；闲着整帧不重绘（canvas 保留上一帧，跳过是无损的，只在「忙→闲」那一帧多画一次收尾）。
公共　一个 useThroughput()：订阅 item.delta，48Hz 采样进环形 buffer，导出 rate / inflight / state。五个方案全接它，先写这个，再挑画法。
