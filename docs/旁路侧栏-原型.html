接着问…↵

「多窗口的感觉」主要来自标签条，不是来自边框。边框只是让它看起来是一块独立的面； 真正让人觉得"这是另一个窗口"的，是它能同时开好几个、能关、能加，而且每个标签有自己的工具条 （审查是 上一轮 ▾ +48 −1，浏览器是前进后退和地址）。 上一版那个下拉选择器同时只能有一条 —— 那是"一个抽屉"，不是"一组窗口"。

要改什么（三条，按代价从小到大）

  1. 分面：一个 token。--bg-sunken 从 #ffffff 改成真凹陷值，.shell 加 gap 与 padding，主区/第三栏套一层 .pane。暗色一个新值都不用 —— 窗口就是现有的 --bg，卡片就是现有的 --bg-raised（白 5%）。要改的是 tokens.css 里「面不分层（全是白的）」那条注释背后的决定，改了就得把理由写进去。
  2. 标签容器：Lane 已经支持，只是界面没这么画。数据层不用动 —— lanes: Record<ThreadId, readonly Lane[]> 本来就是复数。useShell 里那个 asideLane: string | undefined 要变成 { open: string[]; active: string }。关掉一个标签 ≠ 结束那条 lane：lane 还在跑，只是不看了，这两件事得分清楚，否则「×」会变成「杀掉子 agent」。
  3. 内嵌浏览器：这条是新表面，代价最大。Electron 的 <webview> 要单独关掉 node 集成、锁死导航（只许引擎去过的那个域）、处理下载与新窗口请求。而且它只能显示引擎去过的地方 —— 地址栏不可编辑。做成通用浏览器，omni 就得为一个自己没能力维护的东西负责（登录态、扩展、证书…），那是另一个产品。

还有一条不变的硬规则：审批与错误永远不进 lane。 标签化之后这条更要紧了 —— 现在不只是「侧栏关着」，还可能是「开着但在看另一个标签」。 一张正在等你点的审批卡藏在第三个标签后面，比藏在关着的抽屉里更糟：你以为自己看得见。
