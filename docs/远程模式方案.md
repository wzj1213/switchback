# 远程模式：在另一台电脑上用这台的 Switchback · 2026-10-12

> 面向 dev。方向 2026-10-12 拍板，按第 5 节的阶段做。
> 隧道与配对的操作手册仍是 [`远程访问设置.md`](远程访问设置.md)；手机端的设计与取舍见
> [`手机端远程方案.md`](手机端远程方案.md)。本文只写**电脑那一端**多出来的东西。

---

## 0. 一句话

**界面由宿主送出，另一台电脑只当浏览器。**

宿主那台的远程服务端在 `/desk/` 下送出**桌面渲染层本身**——和 Electron 窗口里跑的是同一份构建。
页面里没有 preload，就装一个走 WebSocket、形状与 preload 完全相同的 `window.switchback`，
桌面界面整套跑起来。手机仍然用 `apps/web`。

---

## 1. 起因

用户要在另一台电脑（mac2）上用这台的引擎、会话和仓库。当时手上的两条路：

| 路 | 往返（mac2 上实测） | 缺什么 |
| --- | --- | --- |
| remote-bash：Tailscale 直连本机 | ~365 ms | 不是 Switchback |
| Switchback 手机端：Tailscale → kr → `ssh -R` → 本机 | ~230 ms | 「看住与放行」的手机界面：不能换模型、切档位、接力、分叉，没有审核面板 |

顺带查清的一件事：本机的 UDP 出口绕美国（家里路由的 WireGuard），TCP 不绕。
**kr 那条快，是因为本机这一段换成了 TCP**，不是因为「指定了中转」。
所以远程模式**不新建管子**——就用 kr 那条，只把那一端的界面换成完整的。

---

## 2. 拍板的三个决定

### 2.1 宿主送界面，不让本地界面去连远端宿主

另一条路是「mac2 上装的 Switchback 连本机的宿主」。不走它：

- **版本漂移。** 两台的 Switchback 常年不同版（mac2 要靠推更新包才跟得上），而渲染层和主进程之间
  有 62 条 IPC 通道、改得很勤。让 mac2 的渲染层去讲本机宿主的协议，一错开就是**静默的错**——
  多一个字段少一个字段都不会报错，只会表现成「点了没反应」。宿主送界面，界面和宿主永远是同一份构建。
  VS Code Remote、code-server 走这条路是同一个理由。
- **界面几乎不用改。** 渲染层碰主进程只有 `window.switchback` 一个洞，用到它的 25 个文件都按
  「桥可能不存在」写（`bridge?.x`）。把 3.9k 行的 `apps/web` 补到桌面那个程度，是把 3.5 万行重写一遍。
- **另一台不用装 Switchback。** 浏览器就够；Switchback 里的「连接到另一台」只是一个更顺手的壳（第 4 阶段）。

### 2.2 远程能调哪些通道：逐条点名，表外一律拒

命令（`Command`）那边是**钳档位**（`remote/policy.ts`）：命令再多，也只能让引擎在某条会话里动，
档位钳住了权限面就钳住了，所以「多一条命令不改变权限面」。

**通道不一样，有几类钳不住：**

| 通道 | 为什么只能在宿主上做 |
| --- | --- |
| `tryAcpEngine` / `addAcpEngine` / `acp*` / `installEngine` / `updateEngine` / `rescanEngines` | 在宿主上执行任意程序，或者下载一个包再运行它 |
| `selfUpdate` | 重建并替换宿主自己 |
| `remote/*` | 造新设备、吊销别的设备、改远程服务本身 |
| `settings` 的写（大部分键） | 能把 `remote.maxTrust` 自己调到完全档、关掉外发守卫、启用一家被停用的引擎 |
| `pickFolder` / `pickFiles` / `pickExecutable` / `reveal` / `open*` / `diagnose` | 弹的是**宿主屏幕上**的窗口，远程那一端没人看得见 |

所以 `main/remote/exposure.ts` 是一张表：远程可调的通道，以及每条是「读」还是「写」。
**表外一律拒**——新加的通道默认不暴露，要暴露就得来这张表里加一行，而加这一行是要过评审的事。

设置的写单独一条规则：只放行**界面偏好**那几个键（主题、项目与置顶、排序、项目图标、上次用的引擎、
面板宽度、桌宠）；`remote`、`egressStop`、`zcodeLock`、`disabledEngines`、`defaultTrust`、`dsh`、
`notify`、`handoffBrief` 只能在宿主上改。整条 patch 里只要有一个键不在白名单，**整条拒**——
放行一半等于让界面以为全写进去了。

### 2.3 每台设备一个种类、一个上限

现在档位上限是全局一个值，手机和电脑共用。改成设备记录上带两个字段：

- **`kind`：`phone` | `desk`。** 配对时在宿主上选：手机（看住与放行）/ 电脑（完整界面）。
  **只有 `desk` 能调通道**——手机端本来就不调，少开一个面。老记录没有这个字段，按 `phone` 算。
- **`maxTrust`：这台设备的档位上限。** 缺省沿用 `settings.remote.maxTrust`（老记录不动）；
  设备列表里可以单独改。命令的钳制、通道的读写判据都按它。

通道的两档规则：

- **读**：任何 `desk` 设备都能调。
- **写**（提交、暂存、撤销提交、建 `AGENTS.md`、贴图落盘、存草稿、建对话目录）：
  这台设备的上限要 ≥ 自动审批。**只读上限的设备不能借审核面板绕过只读**——
  它不能让引擎改文件，也就不该能替引擎提交。

## 3. 线上多了什么

`@switchback/wire` 加一对帧。**不进序号**（它们不是「刚发生的一件事」），按 `id` 配对：

```ts
// 客户端 → 宿主
{ type: "call"; id: number; method: string; arg?: unknown }
// 宿主 → 客户端
{ type: "result"; id: number; ok: true; value?: unknown }
{ type: "result"; id: number; ok: false; reason: string }
```

- `method` 就是 IPC 通道名（`switchback:worksite`），`arg` 就是 IPC 那一个参数——
  **宿主那侧调的是同一个处理函数**，不为远程另写一份。
- 结果走同一套分片。大到传不了时回 `ok: false`，**不发 `reset`**：
  一条补丁太大不该让客户端把整份全量重拉一遍。
- `ArrayBuffer`（贴图）在线上编成 `{ $bytes: <base64> }`，宿主还原成 `Buffer`。

其余照旧：`hello` / `replay` / `events` / `ack` / `resync` / `catchup` / `watch` / `thread` / `notice`。
两处对接：

- 桌面渲染层的 `viewing(id)` 在远程模式下就是 `watch`（分级 replay 的补正文、通知去噪都靠它）。
- `thread` 帧（单独补一条会话的正文）经桥上新增的可选 `onHistory` 交给 `reduceHistory`。
  同机 IPC 那条路的全量本来就带全部正文，不会触发它。

**电脑的预算比手机宽。** 全量与单条正文的码元上限按设备种类取（`scope.ts`）：手机那组数是
为 Safari 的内存定的，电脑上照搬只会让长会话无端只剩尾巴。被裁过的会话照样要说出来——
转录区顶上一行「更早的内容没有加载」，不让人以为记录丢了。

## 4. 代码落在哪

| 位置 | 做什么 |
| --- | --- |
| `packages/wire` | `call` / `result` 两种帧的形状 |
| `packages/link`（新） | 浏览器端的连接：重连、心跳、代次、令牌与配对、调用的配对与超时。`transport.ts` / `auth.ts` 从 `apps/web` 挪过来，两个前端共用一份 |
| `main/channels.ts` | 通道登记：`handle(name, fn)` 同时挂到 `ipcMain` 和一张表上，远程按表调同一个函数 |
| `main/remote/exposure.ts` | 远程可调的通道与读写规则、设置写入的键白名单。纯表，表驱动测试 |
| `main/remote/session.ts` | 收 `call` → 查表 → 按设备判 → 调 → 回 `result` |
| `main/remote/tokens.ts` | 设备记录加 `kind` / `maxTrust`；配对码带上种类 |
| `main/remote/static.ts` | `/desk/` 挂桌面渲染层产物（打包时 `Resources/desk`，开发时 `apps/desktop/out/renderer`） |
| `renderer/remote/` | 页面里没有 preload 时：配对屏 + WS 版 `window.switchback` |
| 渲染层若干处 | 远程窗口里藏掉只在宿主上有意义的入口（访达、系统编辑器、引擎安装、自更新、远程访问设置） |

依赖图多一个包：`link ← protocol + wire`；`web` 与 `desktop` 各多一条到 `link` 的边。

## 5. 阶段

1. **本文 + 工程时间线。**
2. **宿主侧。** wire 帧；`main/channels.ts` 与 `remote/exposure.ts`；session 收发 `call`；
   设备种类与上限（含设置页的配对种类和每台上限）。验收：单测覆盖表外拒、手机拒、只读拒写、
   设置白名单；真应用里用脚本连上去调一条读、一条写。
3. **浏览器侧。** `packages/link`（搬过来 + 调用客户端）；渲染层远程启动（配对屏、WS 桥、
   `onHistory`、被裁提示）；`/desk/` 静态挂载；远程窗口里藏掉宿主专属入口。
   验收：隔离数据目录 + 假 ACP 引擎的真应用，无头浏览器打开 `/desk/`，配对、发一句话、看到回答。
4. **壳。** 另一台的 Switchback 菜单里加「连接到另一台 Switchback…」，开一个装着那个页面的窗口，
   只给它剪贴板、查找、系统通知三样本地能力。
5. **远程才需要的。** 新目录（宿主侧的目录浏览）、拖文件做附件（上传通道）、
   文件预览随文件刷新（服务端推）。

---

## 6. 不做的

- **不把两台的会话混进同一个侧栏。** 一个窗口一台宿主。混起来就要回答「这条会话的引擎跑在哪」
  「接力能不能跨机器」——每一个都是新产品。
- **不让本地渲染层去连远端宿主**（版本漂移，见 2.1）。
- **不自己写中继、不改隧道拓扑。** `ssh -R` + `tailscale serve` 够了。
- **不把原生终端搬进来。** 跑原版 CLI 的终端是 remote-bash 的事；
  Switchback 已经能按原生句柄接管引擎那边的会话，两边靠这个接上。

---

## 7. 已知限制（第一版）

- **新建会话只能在已经用过的项目里开。** `pickFolder` 弹的是宿主屏幕上的框；开全新目录去宿主上做，
  或者等第 5 阶段的目录浏览。
- **附件只能贴图。** 拖文件和选择器拿到的是**这台**电脑的路径，宿主上不存在。
- **文件预览不随文件变化刷新。** `watchFile` 要服务端推，第一版没做；重新点开就是新的。
- **页内查找用浏览器自己的 ⌘F。**
- **设置里只能改界面偏好。** 引擎、守卫、远程访问这些去宿主上改。
- **宿主那台得开着 Switchback、不能睡。** 和手机端一样（见「远程访问设置」第 7 节）。
