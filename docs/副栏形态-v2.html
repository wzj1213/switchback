omni · 副栏形态 v2 前沿稿

上一稿的问题不是动效少，是动效说错了话：整条扫光暗示「整条都在工作」，不是——工作只发生在最右端那一寸；Ultra 的渐变永远漂移，可「设置」是静止状态，它一直动，读的人以为它还没完。这稿立四条规矩：① 颜色即状态（紫=在跑，灰=完成，斜纹=排队，红=失败）；② 只有「还活着」的东西才动（now 竖线推进、前沿呼吸、活点泛圈，完成的一律静止）；③ 竖线只有 now 一条——刻度收成底部的尺，满高的竖线是在和条抢戏；④ 特效属于瞬间，不属于状态——Ultracode 的紫从旋钮漫开这一次，到位即静止。

这稿改掉的五件事

① 前沿，不是扫光

旧 · 整条扫光
新 · 只有前沿

扫光说「整条都在工作」——谎话。工作只发生在最右端那一寸，所以光只给那 4px。动效要对准事实发生的位置，否则就是进度条装饰品。

② now 竖线 + 真实刻度

谁和谁是同时在跑、Verify 是不是齐刷刷等齐了才起跳——眼睛靠竖线读，不靠脑补。竖线只留 now 一条；刻度收成底部的尺（0s…到当前），不再拉满高度和条抢戏。

③ 排队不演动画

斜纹段是「派发了但还没轮上」，静止——排队本来就没有进展可演，动了就是谎报。后三个 agent 的起跑线整齐错开，并发上限 3 不用解释。

④ flowbar ＝ 等比缩影

收起副栏后剩下的那条，不是另一套图形——是同一条时间线压到 108px，排队段、在跑段、失败段语义一个不变。两套图形就要学两遍。

⑤ 特效属于瞬间，不属于状态

旧 · 到位还在动
新 · 到位即静止

上一版让渐变永远漂移、还叠一层 3px 抖动马赛克——可「设置」是静止状态，不是进行中的任务；它一直动，读的人以为它还没完。而且靠 @property 注册自定义属性做 mask 羽化，是 Chromium 独占的写法。这版变身只演切换那 0.6s：clip-path: circle 从旋钮圆心漫开，三家浏览器都认，到位后就是一条安静的紫。
