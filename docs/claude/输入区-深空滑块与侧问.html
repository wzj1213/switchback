二、侧问：四种形态

现在是输入区那一排里的一颗带描边的胶囊，点开在它上方弹一个浮层，里面是问答列表加一个小文本框。三处别扭：

它现在别扭在哪

① 站错了队。那一排是「这句话由谁、以什么权限、用哪个模型去跑」——四件事都在描述正文这一句的去向。侧问不改这一句的任何属性，它是另一条通道，却挤在同一排里。

② 它是那一排里唯一带描边的东西。引擎、信任档、模型全是无边的触发器，只有它有边框和背景——在一排安静的胶囊里，它比模型选择器还响，而它远没有那么重要。

③ 为了打字，先开一个更小的打字框。你面前本来就有一个大文本框，问一句话却要：点胶囊 → 浮层弹出 → 点进 2 行的小框 → 打字 → ⌘↩。而且答案只活在这个浮层里，点一下别处就没了——可它回答的正是你屏幕上正在做的事。

我会怎么选

A ＋ D，把 B 当快捷键，不做 C。

A 是主路：一个命令 ＋ 一个模式，不占任何常驻位置。你面前那个大文本框本来就是用来打字的，侧问只是它的另一个去向——这比「为了打字先开一个更小的打字框」顺得多。/侧问 走的是已经有的斜杠面板，发现成本为零，也没有 ? 那种和正常问号撞车的问题。

D 是补路：侧问真正最常见的一句是「屏幕上这段是什么意思」。选中就问把上下文变成隐含的——不用把那段话再复述一遍。这两条覆盖的是两种不同的问法，不冲突。

B 只做键盘那一半（⌥⌘↩ = 作为侧问发送），不做分体键：28px 的圆键劈成两半，主动作那一半只剩 20px 宽，为一个次要动作把主动作变难按，不划算。

C 我不做。docs/侧栏与引擎状态方案.md 里否掉第三栏的那条推理现在仍然成立——这一版的侧问就是一问一答的纯文本，没有工具调用、没有轮次、不流式。抽屉比栏轻，但它仍然是第二个平面，而且平时空着。真出现「一条支线里有多条流式 item」的消费者时，再把它拿出来。

还有一条要你拍板：A 和 D 都把答案放回转录区，做成一张虚线的、明显不属于正文的卡片。这和现在那条「问答不进 transcript」的原则看起来冲突，其实不冲突——那条原则说的是模型下一轮读什么，不是你看得见什么。发给引擎的上下文照旧不含它；界面上让你看见，是因为你问的就是屏幕上这件事。要是你希望它连界面上都不留痕，那 A 的答案就只能停在一张点掉就没的小卡上——那等于回到今天。
