① 模型选择被我吃掉了

上一版那颗触发器写的是 ✧ K3 · 最高 ⌄，点开是强度滑块。可那颗就是 ModelPicker 本人——它现在点开是一个面板、里面「模型」和「推理强度」两节。我把它换成滑块，等于把选模型这件事整个删了。

改成两颗：✧ K3 ⌄ 开模型菜单，最高 ⌄ 开强度卡片，中间只留 2px——它们说的是同一件事（这一轮用多强的脑子），但各开各的面板。你给的第一张图也是这么排的：Opus 5 | Ultracode 两颗并排。

② 为什么上一版拖起来一顿一顿

因为我一边拖一边把它吸附到刻度上：手指走到两档中间时，拇指还停在上一档，两者差出一小段；再走一点它「啪」地跳过去。这就是「不丝滑」的全部来源——不是动画时长的问题，是位置被量化了。

现在拖的时候拇指1:1 跟着指针走，不吸附、不带过渡；松手才落到最近那一档，那一下才用 190ms 的缓动收过去。档位名在越过中点时就跟着变，所以你知道松手会落到哪儿。

③ 紫色是 ultra 一家的，普通档走中性灰

上一版从最低档就开始铺紫，等于把「更贵」那句话说了六遍——说六遍就等于没说，真到 ultra 反而没有升级空间了。这条推理这个仓库写过两次：status.css 说「一刻不停的动画会持续抢注意力」，tokens.css 的用量表那段说「一直是彩色的话，真到危险区就没有升级空间了」。

现在普通档是中性灰坡道（#d4d4dc → #5a5a63，右端 on 白 6.82），只回答「推到多高了」。只有落到 ultra 才整条转紫，星点才亮，边框才扫。

而且引擎不报 ultra 的话，这套紫色从头到尾都不出现。换成 K2.7 试一下：它报三档，条子推到头也还是灰的——不是「灰色版的 ultra」，是这个模型根本没有那一档。

④ 灰 → 紫是交叉淡入，不是硬切

CSS 没法在两个 linear-gradient 之间做过渡——直接换 background-image 是硬切，一帧之内灰变紫，看着像 bug。

做法是两层坡道叠着，只动上层的透明度：灰的那层常驻，紫的那层 opacity: 0 → 1，420ms。中间那段是真的在两套颜色之间走。星点跟着淡入但延后 120ms——先看到颜色变了，再看到星星亮起来，两件事分开说比一起说清楚。

它凭什么这么响

理由是：ultra 是这一行里唯一一个会明显改变花销的开关。ModelPicker.tsx 的 EFFORT 表里，六档只有它带说明，原文就是「更快消耗使用额度」——卡片里那行字是从那儿抄的，不是我编的。它不是「再强一点」，是「这一轮开始烧钱了」。

所以留了那道慢绕的高光：它不是庆祝动画，是常驻提示。你要是忘了自己开着这一档，这一圈会一直提醒。prefers-reduced-motion 下高光和星点闪烁都不出现，颜色、渐变、柔光留着——降级之后信息不丢。

还有一条要你拍板：tokens.css 开头写着「强调色只用于焦点与链接；主按钮用近黑，不用彩色」。这根紫条是这套界面里第一处大面积的、非内容语义的颜色。我认为它值——它标的是花钱；但它确实是对那条规矩开的第一个口子，得是有意开的。

那道扫光是怎么走的

0ms松手，落点是 ultra。紫色先只染卡片自己：条子、标题、那行说明——先说清楚是哪个控件干的。

+60ms描边从底边正中起，往左右两边同时长，620ms 走满一圈在正上方合拢。

+260ms输入框自己那圈边开始转紫，外面那层 3px 的柔光同时浮上来。两条时间线错开，看起来是扫光把颜色「带」过去的。

停住一道高光沿这一圈慢慢绕，4.5 秒一圈。往回拖一格，整套 300ms 内退干净。

为什么是 SVG 描边不是 conic-gradient：圆角矩形的四个角离中心更远，按角度扫描在拐角会明显加速；stroke-dashoffset 走的是周长，哪一段都同一个速度。底边正中在周长上的位置由几何算出来（直边 ＋ 圆角弧长），换窗口宽度自动对。
