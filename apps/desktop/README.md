# @omni/desktop

Electron 壳 + React 渲染层。**这是 omni 唯一的完整主界面**；浏览器端是远程看护界面，
没有面向用户的 CLI。

三个进程角色：

| 角色 | 职责 |
| --- | --- |
| `src/main` | 起窗口；运行 `@omni/host`、引擎子进程与远程服务端 |
| `src/preload` | 只暴露一条窄通道：渲染层发 `Command`，接收 `Event` |
| `src/renderer` | 只认 `@omni/protocol` 的事件模型，不知道任何一家引擎的存在 |

## 拥有什么

- 窗口生命周期、菜单、主题
- 启动历史回放读取已完成的引擎探测快照；探测完成后通过正常事件更新清单，
  远程监听也不阻塞本机开窗。未完成的引擎不会被猜成可用。
- 生产渲染产物压缩，设置中的引擎、安装、环境、远程、活动等页面按需加载。
- 渲染层：会话列表、transcript、审批卡、结构化问题卡、后台终端等待与输入记录、
  原生长期目标、计划快照与常驻进度、composer（图片选择 / 拖入 / 粘贴与拒绝反馈），
  以及只读的后台活动 / 文件工作台
- DSH profile 选择与只读 manifest 投影：展示 bundle 顺序、profile 直接依赖和 patch 状态
- `Command` / `Event` 的 IPC 传输
- **远程服务端**（`main/remote/`）：配对、设备令牌、WebSocket、静态页面、Web Push。
  浏览器端本身是另一个包（`apps/web`），这里只负责把它送出去、并把它接进事件流

## 界面布局与验收

- 侧栏、空会话与 Dock 图标共用 `omni-symbol.svg` 的三线汇合轮廓：上下镜像、等粗笔画、两端等距留白，无半透明叠色。侧栏中英文字对齐基线；图标源稿改动后运行 `pnpm 图标` 更新 PNG / ICNS，并检查 16 / 32 / 64px。
- 浅色使用白色画布与浅灰侧栏，深色沿用同一套文字、边框和选中层级。
  彩色只承担状态和引擎身份；推理强度保留刻度、档位名与用量提示，去掉渐变环和星点。
- 侧栏顶部独立留出 40px 窗口控制区，品牌在下方与导航共用图标列和文字列；标记 20px、名称 16px、导航行 32px。会话顶栏与右侧页签条保持 56px 同高，收起导航时仍以 `--traffic`（92px）避让交通灯。
- 侧栏默认 240px，窗口不超过 960px 时为 224px。正文最大 780px；正文、状态与输入区
  共用 `--content-gutter`（32 / 24px）并补偿滚动条宽度。项目内会话缩进一层。
- 项目会话每页最多挂载 20 行，折叠时卸载；搜索与总数覆盖完整元数据。各项目独立翻页，搜索选中旧会话后自动定位所属页；排序仍按整组持久化。`--sidebar-stress` 使用 503 条会话验收分页。
- 标题/目录筛选的命中结果同样每页最多挂载 20 行，改关键词回到第一页；全文搜索仍保留独立摘要。筛选框显示快捷入口，点清除或按 Esc 返回项目列表并保留输入焦点，向下键进入首条结果；空白关键词不展开搜索列表。
- 临时搜索保留分区折叠、项目展开数量、各项目页码和浏览位置；原列表在搜索时仍卸载。若主动打开搜索结果，返回时展开对应分区与项目并定位所选会话，包含当前已选中的同一条记录。
- 会话悬停预览从等待弹出时就响应滚动、窗口缩放和失焦取消，只有正在预览的行注册监听；翻页、筛选卸载行时释放监听与计时器，改名和拖动时不弹卡。
- 项目内拖动按行的上下半区插入到前/后，末行后也可放；行落点隔离置顶段事件，顺序按全项目保存。分页只改变可见行，Alt + 上下键与右键移动仍使用完整顺序。
- 右侧工具台默认与主对话并排，取可用工作区的 40%，宽度限制为 280–560px；最小窗口也保留主对话和输入区。只有手动点击展开才独占工作区，收起后再次打开恢复并排。正文 body 约束在面板宽度内，Markdown 长段落和代码块默认折行；源码和宽表格保留内部滚动，固定宽度的 HTML 内容仍按原页面布局。
- 转录区左缘那条大纲**钉在左缘**，位置不随正文列漂；舞台窄于 920px（正文左边的空档
  容不下 `--rail-lane + --rail-clear`）时整条不画。门槛按 `--content-max` /
  `--content-gutter` / `--bar-w` 算出来，`transcript-rail.test.ts` 里有守卫盯着它别再漂。
- 纯等待 / 纯状态那一屏（「正在打开工作区…」「还没有会话」）两个方向都居中；
  有下一步动作的空态（新会话）仍与正文、输入框共用同一条左缘。
- 分栏开合（收起导航、开关工具台、顶栏给交通灯让位）共用 `--dur-shell` / `--ease-shell`，
  同一帧起跑同一帧落定；`prefers-reduced-motion` 下全部瞬切。
- 输入区左侧放附件与审批，右侧放用量、引擎、模型和强度；可用宽度不超过 620px 时分两行。
  文件改动默认显示本轮摘要，展开才挂载明细，审核入口始终可用。
- 长会话的大纲独立订阅滚动，隐藏时不测量正文；已完成回答在屏外延迟排版，完整 DOM 保留供全文查找。`node scripts/shot-app.mjs /tmp/omni-stress --stress --audit --reduce` 用 240 轮固定记录验收。首次打开仍需解析完整会话，未做历史记录截断。
- 设置保留固定外框与独立滚动，主题采用可点选的预览，键盘焦点仍锁在弹窗内。
- 普通操作的 hover / 按下、选中项的加深反馈与键盘焦点由 `interactions.css` 统一；底色使用语义 token，选中不会在悬停时退回普通态。禁用控件不响应悬停变色；危险确认保持可读的红色反馈，主按钮与拨块保留语义样式。侧栏行内操作在当前行悬停或键盘进入时显现，尺寸不随状态变化。

先构建，再用隔离数据运行实际 Electron 巡检：

```sh
pnpm --filter @omni/desktop build
node scripts/e2e-smoke.mjs
node scripts/shot-app.mjs /tmp/omni-ui --audit --reduce --engine=codex \
  --views=01-转录区,01b-收起侧栏,01c-每轮的改动卡,01c-展开本轮文件,01d-提问导航条,03-环境信息,14-新会话,18-输入区布局,18-模型菜单焦点,18-超长模型名不出界,18-推理强度,19-设置
```

`--min` 验 860×560，`--dark` 验深色。模型与强度场景需要所选原生引擎在本机已安装并能初始化；
巡检只读取清单、切换档位，不发送任务。设置分类会自动逐页截图和执行 axe A/AA 检查。

### 回答链接、文件阅读与本轮补丁

- 回答中的 HTTP(S) / mailto 链接交给系统浏览器；本地文件链接进入侧栏预览。
  支持绝对/相对路径、`file://`、中文与 URL 编码路径，以及 `:行:列` / `#L行` 定位；
  文档中的相对链接以文档目录解析，聊天回答以会话工作区解析。读取仍经过主进程的工作区与触达记录校验。
- 点击每轮「已编辑」卡的文件或查看按钮，展示该轮引擎上报的编辑记录。
  同一文件多次编辑按原始顺序保留，默认显示最后一次；卡片统计继续采用每文件最后一次上报。
  该视图不依赖文件今天是否还存在、是否已提交、是否在 Git 仓库中。
- 本轮补丁支持文件筛选、上一份/下一份、单栏/并排、复制反馈；并排宽度不足时展开面板。
  「Git 差异」打开原有工作区审核范围，不把两种来源混为同一份净改动。
- 文件源码显示行号与语法色，Markdown 可切换阅读预览/源码；长文件采用视口挂载，
  完整显示范围的复制仍读取原始文本。带行号链接重复点击也会重新定位。
- 文件预览的前后箭头与 Option/Alt + 左右方向键可在文档、代码间往返，保留链接的行列号和锚点。
  每个方向最多保存 30 个目标，历史不跨任务/工作区，也不落盘；点击「文件」回到索引并结束阅读链。
  文件刷新保持当前阅读位置，只有新的定位请求才滚动到目标行。带参数的行内命令保持普通代码。
- 交互验收：`scripts/shot-views-links.mjs`，由 `scripts/shot-app.mjs --audit` 驱动，
  覆盖历史补丁、复制、并排、缺失补丁、链接定位、文档相对链接与五万行源码。

## 不拥有什么

- **不拥有引擎驱动**。渲染层不 spawn 进程、不解析任何一家的协议。
- 不拥有审批判定。判定在 `@omni/approval`，这里只渲染 `escalate` 出来的卡片。
- 不拥有持久化。落盘在 `@omni/journal`。
- 不拥有业务编排。跨会话、跨引擎的编制在 `@omni/host`。
- 不拥有 DSH 插件生命周期。安装、升级、Provider、模型与凭证仍走 DSH 自己的入口。

## 为什么 desktop 直接依赖了 Claude 的 SDK

`@omni/engine` 是 workspace 源码，会被**打进** main 进程产物。产物因此继承了
engine 的运行时依赖，而 Node 从产物所在目录往上找 `node_modules`——
所以这些依赖必须出现在 app 根目录，否则运行时报 `ERR_MODULE_NOT_FOUND`。
每新增一个引擎驱动，它的运行时依赖都要在这里跟着加一条。

## 完整版与轻量版

两种包都使用 Claude Agent SDK 与用户原生登录态，差别只在 CLI 从哪里来：

```sh
pnpm dist        # 完整版：带 SDK 对应平台的 Claude 可执行文件
pnpm dist:thin   # 轻量版：排除平台二进制，要求 PATH 上已有 claude
pnpm dist:all    # 构建一次前端，再依次生成两种 DMG
```

版本、短 SHA、源码路径和 `claudeExecutable` 只写进 electron-builder 的临时配置，
不会改动源码 `package.json`；它保留 `0.0.0` 是有意的。每次成功生成安装包后，
`prune-release.mjs` 自动只留最新三组产物，blockmap 跟着对应安装包一起清理。

## 签名与公证

配置已经就位（`electron-builder.yml` + `build/entitlements.mac.plist`），
**缺的只是凭据**。齐了之后一条命令就能出签名包，不用改任何代码：

```sh
CSC_NAME="Developer ID Application: <名字> (<TeamID>)" \
APPLE_ID=... APPLE_APP_SPECIFIC_PASSWORD=... APPLE_TEAM_ID=... \
pnpm dist:signed
```

`pnpm dist` **永远不签名**（它显式设了 `CSC_IDENTITY_AUTO_DISCOVERY=false`）。
这不是保守：不关的话 electron-builder 会去翻钥匙串、抓到任何一张证书就开始签，
而一张不受信任的证书会让 `codesign` 卡在逐个文件签名上——实测跑了 400 秒
还停在 `locale.pak`，得手动 kill。

需要三样：Apple Developer Program 会员（99 美元/年）、钥匙串里的
Developer ID Application 证书、App Store Connect 的 app-specific password。

### 强化运行时已经验过了，不用等证书

公证强制要求强化运行时，而**强化运行时默认会掐掉 omni 赖以工作的两件事**：
V8 的 JIT，以及「加载别人签的二进制」——后者正是这个产品的核心
（spawn codex / ACP 适配器 / Claude SDK 自带的 CLI）。
等付完钱那天才第一次打开它，就要在最不该调试的时刻调试它。

用 ad-hoc 签名可以提前把这条路走完（`--sign -` 不需要任何证书，
但一样应用 `--options runtime` 与授权清单）：

```sh
codesign --force --deep --options runtime \
  --entitlements apps/desktop/build/entitlements.mac.plist \
  --sign - release/mac-arm64/omni.app
codesign -d --verbose=2 release/mac-arm64/omni.app   # 应含 flags=…(adhoc,runtime)
codesign -d --entitlements - release/mac-arm64/omni.app
```

已实测：`flags=0x10002(adhoc,runtime)`、六条授权全部生效，
应用能起、渲染层能画、`which` 探测能跑、codex 子进程能 spawn 并读文件。
**如果哪天加了新的原生依赖或新的子进程，重跑一遍这三条命令再发版。**

## 本机自更新：改完代码，在应用里点一下

装在 `/Applications/omni.app` 的那份是从**这台机器上的源码**打出来的，所以
「让刚改的代码生效」这件事不必绕一圈终端。侧栏底下那一行（`UpdateRow`）
在**有源码比这份包新**时出现，点它就是：

```
pnpm --filter @omni/desktop run dist:local   # 只出 .app，不打 DMG（实测 ~11 秒）
ditto → 换掉 /Applications/omni.app → open   # 由一个独立脚本在应用退出后做
```

三件事值得知道：

- **判据是文件时间，不是版本号。** 版本号来自 git 提交数，而开发时的改动
  大多还没提交——按版本号比，改完它会说「已经是最新」。所以直接问文件系统：
  有没有源码文件比装着的这份包新（`find -newer`，剪掉 node_modules/.git/release/out/dist）。
- **源码路径是打包时烤进去的**（`omni.repo`，见 `scripts/dist.mjs` 的临时元数据）。
  包拷到别人机器上时那个路径不存在，这一行**整个不出现**——不是灰掉，是不画。
- **换包在应用退出之后由独立进程做**：等旧进程真的退出 → `ditto` 到旁边 →
  同目录两次 `mv`（同盘原子）→ 失败就把旧的挪回来。这一步没有界面能报错，
  所以它有一条**真跑一遍**的测试（`selfupdate.test.ts`）。

第一次（或者按钮本身坏了）手动装：**先退出 omni**，然后

```sh
pnpm --filter @omni/desktop run dist:local
ditto release/mac-arm64/omni.app /Applications/omni.app.新 \
  && rm -rf /Applications/omni.app \
  && mv /Applications/omni.app.新 /Applications/omni.app \
  && open /Applications/omni.app
```

## 更新检查（远端）

**只查不装，这是有意的。** macOS 上装更新走 Squirrel.Mac，而它会校验新旧两个
版本的代码签名——没签名的应用它根本不会给你装。硬塞一个 `electron-updater`
进来只会在下载完之后卡在安装那一步，而**一个走到最后一步才失败的更新流程，
比没有更新流程糟**。

feed 地址填在 `apps/desktop/package.json` 的 `omni.updateFeed`
（`OMNI_UPDATE_FEED` 可覆盖，企业内网自建源用得上）。**留空 = 整个功能不存在**：
不发请求、不起定时器、菜单里也不出现「检查更新…」。

源返回一个 JSON：

```json
{ "version": "1.2.3", "url": "https://…/omni-1.2.3.dmg", "notes": "改了什么" }
```

`url` **只认 https**——一个能被改成 `http://` 或 `file://` 的更新地址，
就是一条能把用户引去任意地方的路。

## 通知：出声的四件事

「跑完了 / 跑挂了 / 有人等你批 / 有问题等你答」会发系统通知（`main/attention.ts`）。四条克制：
正在看这条会话不弹、同一件事只弹一次、**15 秒以内跑完的不弹**（那种你八成还盯着屏幕）、
**自己按停的不弹**（那是你刚做的动作，报告它等于回声）。

窗口在前台但你看的是**另一条**会话时照样通知：渲染层通过 `omni:viewing`
只报当前会话 id，主进程不读取界面状态。启动首帧还没报上来时保守地不弹，避免乱响。

Dock 角标只算**挂起的审批与问题组**，不算在跑的轮次：角标是「有事等你做」，不是「它在忙」。

## 长任务：挡待机 + ⌘Q 确认

有会话在跑、等审批或等结构化回答时，主进程持一个 `powerSaveBlocker`（`main/awake.ts`），
全部落定才放开。
同一批判据（`busy()`）也决定 ⌘Q 要不要先弹确认（`main/quit.ts`）——闲着的时候一句不问，
因为每次退出都弹框，人很快就学会闭着眼按回车。

三件给不出的承诺，写在这儿免得日后当成 bug 查：

- **合上盖子照样睡。** macOS 的 clamshell sleep 没有任何电源断言拦得住。
- **只挡闲置待机，不挡屏幕休眠**（`prevent-app-suspension`，不是 `prevent-display-sleep`）。
  后者会让笔记本亮一整夜——那是把一个小问题换成一个更烦人的问题。
- **非 mac 上关掉最后一扇窗不问确认**（`window-all-closed` 走 `quitNow()`）。
  那时已经没有窗口了，点「取消」会得到一个没有窗、没有托盘图标、
  只能去任务管理器里找的应用——比静默退出更难收场。

## 远程访问：手机上看住它

`main/remote/` 起一个**只听回环**的 HTTP + WebSocket 服务端（没有绑公网的开关；
要从外面进来就开隧道，那条路是显式的、可撤销的）。桌面窗口和手机是**对等的两个客户端**
——同一份编号、同一条事件流（`sink.ts` + `@omni/wire`），不是「主界面 + 一个远程视图」。

四条判定在这一侧，不在浏览器里：**档位上限**（远程默认 `auto-edit`，钳的是档位不是命令白名单）、
**`Host` 头闸**（绑回环挡不住 DNS 改绑，浏览器是可以被骗的代理人）、
**记忆范围收窄**（远程的 `project` 级规则降成 `session`）、**分级 replay 的预算**。
界面上的限制只是提示——那份 JS 跑在用户的浏览器里。

操作手册（含隧道、换密钥、丢了手机）见 [`docs/远程访问设置.md`](../../docs/远程访问设置.md)。

## 审核面板

⇧⌘R 打开当前 Git 审核；每轮改动卡打开该轮原始编辑记录，面板中的「Git 差异」可切回当前范围。
默认单栏并自动换行，文件列表按面板宽度放在右侧或上方；支持并排、行号、文件导航与当前文件预览。

数据来自 **git**（`main/workdiff.ts`），不是引擎报的编辑——引擎用 shell 写的文件、
你自己改的、上一轮留下的，在引擎报的那份里一个都没有，而「要不要提交」问的是
工作区的真实状态。清单一次问清（两条 git 命令），**补丁按需取**：一个 200 文件的
改动全量取可能是几十 MB，而人一次只看得了一个。

三条边界：

- **不做提交、不做还原、不碰暂存区。** 面板只读。写 git 的动作要有撤销路径，
  而这里还没有——在那之前不提供一个「点了就回不去」的按钮。
- **不把 diff 交给另一家引擎去审。** 那要为 agent 之间发明协议（见 `AGENTS.md` 的边界）。
- 二进制、超过 400 KB 的单份补丁、超过 500 个文件：照实说不显示，**不假装没有**。

## 跨会话正文搜索

侧栏 ⌘K 打的词，除了标题/首句/目录，还会去 `userData/threads/*.jsonl` 里找正文
（`main/search.ts`）。结果单独一段，慢半拍出现——上面那份必须逐字即时，它是主路径。

- **只搜 `user_message` / `agent_message`，不搜 `tool_call`。** 把命令原文算进来的话，
  搜「review」会命中每一条跑过 `git diff` 的记录，噪音会把真正想找的那句埋掉。
- **多个词是「与」，但不要求在同一条消息里**：「omni 流式」找的是「在 omni 那条会话里
  聊过流式」，那两个词多半分散在不同轮次。
- 预筛之后才 `JSON.parse`（原始行里一个词都没有就跳过）。本机 5 MB 实测 27ms；
  48 MB 预算用完就停，剩下几条**照实报给界面**。

## 输入区文件引用

在输入区键入 `@` 搜工作区文件，上下键移动，Tab / 回车填入，Esc 关闭。候选搜索会区分加载中、
零命中与失败；失败可原地重试。这里只引用引擎能自己读取的工作区路径，不上传文件内容。

## 任务工作台

顶栏「活动 / 文件」共用右侧工作台，默认与主对话并排，手动展开才独占工作区。
按 Esc 收起；文件搜索已有关键词时，第一次 Esc 只清关键词，第二次才收起工作台。

## 已知限制

- **历史补丁只展示引擎实际提供的文本。** 没有提供正文时显示缺失说明，并保留当前文件预览与 Git 审核入口；
  单份超过 1.5 MB 或 10000 行不挂载，不尝试根据现在的文件反推历史。修改片段没有 hunk 位置时不生成行号。
- **大文件阅读有显示上限。** 文本仍由主进程限为前 1.5 MB，语法高亮限于 3000 行和 200 KB；
  超过 3000 行只挂载视口附近的源码行，跨越未挂载行的鼠标选择不完整，需用「复制」获取显示范围全文。
  Markdown 超过 200 KB 或文本截断时使用源码模式。行定位按当前内容的行号，不保证与历史补丁位置相同；列号暂不单独高亮。


- **输入区附件目前只支持图片。** 只有当前引擎与模型明确公开图片能力时才显示选择入口；
  PNG/JPEG/GIF/WebP 单张不超过 12 MB。各家现有公开出口没有统一的任意源文件附件，普通文件
  请用 `@` 引用工作区路径；omni 不把路径或自写提示词塞进模型上下文冒充文件附件。
- **文件预览只跟踪当前打开的文件。** 原生文件事件触发重读，会话读写、轮次状态、窗口聚焦和
  15 秒轮询负责兜底；不会轮询整个工作区。文件系统事件丢失时可能存在刷新延迟，也可手动「重新读取」。

- **HTML 预览只完整支持自包含页面。** 预览 iframe 没有同源权限，也禁止网络访问；相对路径的
  CSS、图片和脚本不会替页面偷偷读取。需要核对这类项目页面时仍应从它自己的开发服务打开。
- **文件工作台只读两类文件：当前工作区里的，和这条会话自己碰过的。**
  后者的名册在主进程按事件流记（`main/touched.ts`），渲染层说了不算；名册按会话与路径两级
  淘汰（40 条会话 × 1000 条路径），被淘汰的老路径退回「工作区外」那句提示。
  两类之外的越界路径与离开工作区的符号链接一律拒绝；文本只取前 1.5 MB，
  图片最长边缩到 1600px，二进制文件只说明不能预览，不尝试猜格式。
- **打出来的包仍然没有签名**：本机只有一个自签且 `CSSMERR_TP_NOT_TRUSTED` 的证书，
  electron-builder 会拒绝用它，于是照旧 skip 签名。上面那段配置只有在
  `CSC_NAME` 指向一个真证书时才生效。首次打开仍需在「隐私与安全性」里放行。
- **Linux / Windows 的包必须在对应平台上打。** Claude Agent SDK 的原生二进制
  按平台分包，现在已经显式列进 `optionalDependencies`（每个都带 os/cpu 字段，
  所以本机只装 darwin-arm64 那一个，不占地方）。但**在 macOS 上交叉打 Linux 包
  仍然拿不到 linux 的那个**——那台机器上根本没装。CI 的三格里各打各的才对。
  在真机上跑过之前，这仍然算未验证。
- **只在 macOS 上验过。** 平台差异收在 `@omni/engine` 的 `platform.ts` 一处：
  查命令（`which` / `where.exe`）与进程树回收（负 pid 信号 / `taskkill /T /F`）。
  Windows 那几支**没有在真机上跑过**——写它们是因为原来的实现在 Windows 上
  是默默错的（负 pid 不是进程组），错得无声无息比明说不支持糟得多。
  另外那边拿不到「整树退出证明」，`TreeControl.provesWholeTree` 会照实报 false。
- **引擎探测会错，所以从不硬拦。** 探出「未安装」的引擎在选择器里只加个记号，
  照样能选——灰掉一个其实能用的引擎，比不检查更糟：用户会相信自己没装，去装第二遍。
  只有一键分叉会跳过它们（那个动作没有确认步骤）。
- **崩溃转储只留在本机**，一个字节都不上传（`uploadToServer: false`）。
  转储里可能有内存快照，而内存里装着用户的代码与提示词。诊断报告只列文件名和时间。
- **主进程崩溃只能靠下次启动时发现**（运行标记文件）——主进程死了就没人记日志了。
  正常退出删标记，下次发现标记还在就说明上次是崩着走的。
- **补发缓冲只有 5000 条。** 超过这个的缺口补不回来，渲染层会重载页面走全量重建。
  这不是静默降级：主进程会记一条 `补发失败` 到日志里。
- 完整版的大头是 Electron 运行时与 Claude SDK 平台 CLI；轻量版去掉后者，但要求本机安装 Claude。
- **变更汇总卡不能给本次对话里的每次写入归因。** 会话开场基线已经能把开场前的脏文件
  与本次最终留下的 Git 净差异分开；上半节的编辑工具上报也能追到对应工具行。但基线之后
  同一个文件究竟是引擎跑命令改的，还是用户在编辑器里改的，Git 不记录这个来源，界面也不猜。
- `⌘F` 查找覆盖**整个窗口**，侧栏预览与查找框自身也算命中——
  排掉它们需要让输入框不可输入，而中文 IME 需要一个真正获得焦点的 input，
  不划算。计数上挂了 tooltip 说明。
