# @switchback/worksite

工作区的文件索引与模糊搜索。**引擎无关。**

放在引擎之外是有意的：`@` 引用文件是**工作区**的事，不是某一家引擎的事。
codex 有 `fuzzyFileSearch`，Claude 没有——真按引擎各做一份，两家的排序质量
就会不一样，用户会觉得「换个内核连搜文件都变了」。

## 拥有什么

- `createWorksite(root)` —— 带 TTL 缓存的文件索引 + `search(query)`
- `score.ts` —— 子序列匹配与打分，**纯函数**，排序质量能被穷举测试

排序上最重要的一条规律：**文件名比目录名重要得多**。搜 `host` 时
`src/host.ts` 必须排在 `src/host/util.ts` 前面，更要排在
`packages/host-x/deep/thing.ts` 前面。四个信号：连续命中、词首命中、
落在文件名部分、路径长度。

## 不拥有什么

- 不读文件内容。只索引路径。
- 不理解 `.gitignore`。用的是一张硬编码的跳过表（`node_modules`、`dist`…）——
  解析 gitignore 要引一个库，而那张表已经覆盖了 99% 的情况。
- 不监听文件变化。靠 15 秒的 TTL，不靠 watcher。
- 不做引擎那边的 `mention` 协议翻译；本包只回相对路径。

## 已知限制

- **索引上限 2 万个文件、深度 12 层**，到顶就停。一个几十万文件的仓库里，
  排在后面的文件搜不到。这是有意的：`@` 不该变成一次全盘扫描。
- 隐藏文件除 `.env` 外全部跳过。
- TTL 15 秒：刚 `git checkout` 出来的新文件最多要等 15 秒才搜得到。
- 打分是**贪心**逐字符匹配，不是最优子序列。路径这个场景下差别极小，
  但确实存在构造得出来的反例。
