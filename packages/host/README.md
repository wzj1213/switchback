# @switchback/host

会话编制与进程生命周期。**唯一允许做编排的地方**——其余包都只做一件窄事。

宿主拥有 thread / turn 的身份，引擎拥有 item 的身份。这条分工是有意的：
prompt 是宿主发出的，所以宿主知道一轮什么时候开始；引擎知道自己产出了什么，
所以 item 由它铸造 id。`turn.completed` 由引擎发（只有它知道自己什么时候真收工）。

## 拥有什么

- `createHost(deps)` —— 命令分发（`Command` → 引擎）与事件汇聚（引擎 → `Event`）
- 会话注册表：thread id → 活着的 `EngineSession`
- 审批闸（`gate.ts`）：把驱动的 `askUser` 变成一张 transcript 里的审批卡，
  等渲染层的 `approval.resolve` 命令来落定；引擎先撤销时标成失效并解开等待。
  主轮之外来的（后台子 agent、workflow 在主轮收工之后才来要权限）挂在会话上（`outside.ts`），
  不替引擎拒；「本轮剩下的都放行」不放过任何带来源（`origin`）的请求
- 结构化问题闸（`question.ts`）：把驱动的 `askQuestion` 投影到 `Thread.pendingQuestions`，
  严格核对题目、选项、备注与答案形状，再由 `question.resolve` 原样回给仍在等待的引擎；
  引擎取消或非阻塞期限到达时清卡并按跳过落定
- **会话状态**（idle / running / waiting_approval / failed）。只有宿主同时看得见
  「提示词发出」「审批挂起」「轮次收工」这三件事，所以状态归它改。
  轮次收工是引擎直接发给渲染层的，宿主看不到——所以在传给驱动的 `emit` 上截了一道
- **轮次发送前的外部快照时点**：host 只在即将开启新 turn 时调用依赖注入的工作树快照钩子，
  并等待完成后再把提示词交给引擎；Git 如何取样、保存在哪里仍由 desktop 拥有，host 不读工作区。
- **引擎主动轮次的主线身份**（`native-turn.ts`）：引擎公开调度能力或同会话其他原生客户端在空闲时开轮，
  宿主仍负责铸 turn / user item id、让临时会话转正并进入 running；已有轮次或旧会话代际不得覆盖。
  原生长期目标的后续 turn 由驱动留在同一宿主轮；只有断线时直接撞上续轮，才以空正文和结构化来源接入，
  续接、收编或分叉的旧 transcript 也会先复制完成；需要实时订阅的驱动最后才 `activate()`，
  避免抢先到达的原生轮整段无主或排到旧历史之前
- **事件的唯一出口**（`emit()`）：转发给渲染层 → 落盘 → 旁路观察。
  所有发事件的地方都必须走它，落盘才不会漏。每一条还先过一遍出字节奏的账本
  （`@switchback/store` 的 `pace.ts`），收工那一条带上这一轮的 `pace` 再发——
  只有这里看得见每一条会话的每一条增量，而增量本身不落盘
- **旁路的身份与主线闸门**（`item-scope.ts`）：引擎给的 lane id 重铸成 Switchback 全局 id
  （理由同 item——一条会话会中途换引擎，两家都报 `t1` 时后一条会盖掉前一条；
  item 原来那个 id 留在 `nativeId` 上，交接转写靠它到原始记录里对位），
  item 上的 `lane` 归属跟着重铸；**`kind: "approval"` / `"error"` 的 `lane` 一律剥掉**
  （`mainlineOnly`）。写成运行时闸门而不是文档里的一句话，是因为类型表达不了
  「这两种 kind 不许有这个字段」，而只写在文档里的约束，接第五家引擎时没人会记得
- **侧问生命周期**（`engine-state.ts`）：用户发出后先铸 `kind:"aside"` 的运行中 lane，
  原生答案或原始错误以同一 id 收口；不创建 turn、不产生主线 item，也不把单次失败冒充引擎崩溃
- **回声闸**（`echoed()` / `echoKey()` / `shapeOf()`）：item 的开始、更新、撤回与
  `thread.updated`，**除时间戳外和上一条逐字节相同就整条丢掉**。
  丢掉的字节数是零——那样一条对归约器、渲染层、journal 三边都是空操作。
  挡在出口而不是各家驱动里，因为它不只是某一家的毛病：ACP 那条线把同一份工具投影
  翻译出来 9793 遍，而 `thread.updated` 是宿主自己十几处各发一遍的
- **活会话背后的引擎进程**（`processes()`）：每条活会话的 thread / 引擎 / pid（驱动报了才有；
  kimi web 这种几条会话共用一个进程的会出现几行、pid 相同）。桌面端外发守卫用它，宿主自己不看流量
- **活状态快照**（`live-state.ts`）：额度、命令、历史、账号、思考进度与正在运行的子任务
  不写 journal，但各留最后一帧供窗口重建；任务与思考在对应轮次终态清除
- **临时会话的生老病死**（`Thread.provisional`）：新建出来先是临时的——引擎照起
  （模型清单、斜杠命令要它才有），但**不落盘、切引擎当场生效、建下一条时把上一条收掉**；
  发出第一句话才转正。界面据此决定它进不进侧栏
- **历史会话接回引擎**（`revive.ts`）：宿主手上没有的会话，发话时先接回来——原来那家在、留着句柄就续它那条原生会话，
  记着 `nextEngine` 就直接起那一家（和活会话换引擎同一套，`switched.ts`）。在历史会话上挑引擎、改档位只改记录
  （整份重发并带上 `detached`），不起进程。接不回来就还原成历史记录，发话那条路把那句话退回输入框（`draft`）。
  历史会话上排着的「待发送」也照样取回（`take-back.ts`）：摘出记录里的队列、放进 `draft`，不起进程
- **删掉的会话不再报错**：命令跑到一半这条会话被删了（临时会话被下一次「+」收掉最常见，那时它的
  切换握手还没走完），失败是删除带来的，`dispatch` 安静收场，不让界面为一条已经不要的会话弹横幅。删除本身失败照报
- 信任档需要重建原生沙箱时，在空闲状态续接同一引擎句柄重启；运行中不打断、不先写假状态
- 引擎原生目标的持久镜像：运行期更新/清空走 `thread.updated`，握手期快照并入出生事件；接力不串家
- 处置：`dispose()` 关掉全部会话，把还挂着的审批**按拒绝 settle**、问题**按跳过 settle**
- **换引擎自动交接的时机**（`handoff-note.ts`）：只在「换家后的第一句」上向
  `HostDeps.handoffBrief` 要一段交接说明——判据是最后一段记录不是当前这家
  （新那家说过话、落下自己那一段之后自然不再成立）。拿到了就作为 `origin: "handoff"`
  的用户消息排在这一轮最前面，并以「说明＋空行＋用户那句」送给引擎；拿不到照旧只发那一句

## 不拥有什么

- **不拥有审批判定**。判定在 `@switchback/approval`，宿主只负责把「需要人」这件事送到界面。
- 不拥有引擎协议。各家的握手与消息翻译在 `@switchback/engine`。
- 不拥有视图状态。归约在 `@switchback/store`，宿主只发事件。
- 不拥有 UI、IPC 传输。
- 不拥有落盘格式。宿主只是把事件交给 `@switchback/journal`，字节怎么排是那边的事。
- **不拥有交接说明的内容与开关。** 转写落盘、读原始记录、用户关没关都在调用方
  （桌面端 `main/handoff-brief.ts`）；宿主不碰文件。

## 「本轮剩下的都放行」

审批卡下拉里的那一项。它**省掉的是打断，不是判定**，所以三条边界一条都不能松
（`approval.ts` 的 `passes`，测试在 `passturn.test.ts`）：

- **红线照旧逐条问。** 红线（`@switchback/approval` 的 `REDLINES`）正是最不该被一次点击盖掉的；一个能盖掉红线的按钮
  等于把档位机制整个绕过去。驱动因此要把 `verdict.redline` 透传进 `ApprovalAsk`——
  不带的话宿主分不出「档位升级上来的普通请求」和「凭据读取」。
- **存的是轮次 id，不是布尔。** 失效因此不需要任何人记得去清：下一轮 id 不一样，
  比较自然就不成立了。布尔要在 `turn.completed`、被打断、切引擎、会话回收四处各清一次。
- **armed 之后不发卡。** 再弹一张「已自动允许」的卡，等于把用户刚想省掉的打断
  原样还回去。做了什么在工具行里照样看得见，而且 `Thread.passTurn` 会让界面
  亮一枚「本轮已放行」——这个状态不该只活在宿主内存里。

## 已知限制

- **主轮之外来的审批只认引擎报的来源，认不出就照实写「来源未标明」。** 主轮收工之后才来要权限的
  （Claude 后台 workflow 里的子 agent、Kimi 后台任务）挂在会话上（`Thread.pendingApprovals`），
  输入框上方等人点，主轮收工、按停止都不收它（`gate.settleTurn`）。卡上写「谁要的」只用引擎报的 id：
  Claude 的 `agentID`、Kimi 帧上的 `agentId`；ACP 的 `session/request_permission` 不带来源，codex 也没接。
  Claude 的 `agentID` 和 workflow 旁路（整批共用一个 task_id）不一定一一对应，所以不去对旁路猜名字。
  落定之后不在转录区留记录——没有轮次可挂。
- **被收起的判据只看得到引擎报着的子任务。** `evict` 不收挂着这类请求、或活状态里还有子任务的会话；
  Claude 在主轮收工时清掉子任务进度，此后仍在跑的后台 agent 宿主看不见，最久没动的那条照样可能被收起。

- **不做背压**。`emit` 必须同步返回得比引擎产出快，否则事件在内存里堆积。
- **回声闸只认 item 快照变化与 thread.updated，而且只比对上一条。** `item.delta` 永远放行（两条一样的增量是
  两次真的追加）；`turn.*` / `thread.started` 描述的是一次发生，不是一份现状；
  活状态那几种自己就按键留最后一条。A → B → A 会发三条，因为记的是
  「上一次发出去的样子」，不是见过的所有样子。item 指纹按 turn 隔离并只清完成的那一轮；
  多会话并行时不会互相冲掉账本。thread 快照每条会话只占一个键。
- **它挡的是症状，不是病灶。** 驱动或宿主自己在重复发事件仍然是 bug：白写的
  `JSON.stringify` 和 `synthDiff` 都发生在这道闸门之前。闸门存在的意义是
  **32 MB 那条硬线后面是整条会话不再落盘**，不能等每一处都自觉。
- **同时活着的引擎会话有上限（默认 4），超了就把最久没动的空闲会话收掉**，
  标成 `detached`，下一句话发出去时自动接回来（记录、句柄都不动）。
  量出来的（这台机器，codex）：**7 条会话 28 个进程 1.83 GB；上限 4 之后
  16 个进程 1.06 GB**。重点不是省了 42%，是从「开几条涨几条」变成了有上限。
  四种绝不收：正在跑的、等着审批的、等着回答结构化问题的、没有引擎句柄的
  （最后一种收掉就回不来了）。
- **回放出来的会话发话时才接回引擎**，接回要起进程，这一句会晚几百毫秒到几秒开轮。
  引擎那边的对话记忆要靠 `engineHandle` 续跑才回得来；没有句柄的旧记录**不用原来那家静默新建**
  （起一个全新会话却看着像接上了，是最坏的结果），报错并提示换一家——换家是明确的动作，不算冒充。
- **接回时不排空历史队列。** 记录里留着的待发消息（`queued`，上次失败或中断时剩下的）
  接回后仍是「待发送」，由人取回或等下一轮跑完再发，和以前点「继续」一样。
- **记忆规则不做跨工作区共享**。`project` 级规则按工作区路径分文件存；
  换一个目录就要重新勾一次。全局级还没有——它的风险面比 project 大得多，
  值得单独设计而不是顺手加一档。
- **接力（L2）不搬运模型上下文，也不注入摘要。** 各家原生会话格式不通；
  Switchback 只在 `Thread.segments` 里保存引擎确实公开的原始记录路径（若有）并展示在时间线。
  用户开着「换引擎自动交接」时，换家后的第一句话前附一段只陈述事实的说明（转写与原始记录
  在哪、是什么格式），读不读、读多少由新那家定；关着就由用户自己给路径。
- **交接说明要读盘，这一句会晚一点开轮**（读会话记录、写转写，长会话约几百毫秒）。
  等的期间会话若被换掉、或引擎自己开了一轮，这句交回主路重新判定（排队或重发）。
- **新那家第一轮没拿到句柄就失败时，下一句会再附一次说明。** 它手里还没有接得住的原生会话，
  再附是对的；代价是转录区会出现两条「历史交接」。
- **接力之后旧引擎的进程就没了**，但那条会话还回得去：每一家的句柄各存各的
  （`Thread.segments`），切回去续的是它自己那条。代价是切回去要重新起一次进程。
- **`Thread.segments` 是一条时间线，不是一张名单**：A→B→A 记三段，第三段和第一段
  句柄相同、时刻不同。去重只和**最后一段**比（同一家连着跑多少轮仍然只记一段），
  而且仍然只在那一段真的开跑时才落——切过去没说话就切走不留记录。
- **换过去的那家起不来时，会原样退回旧那家**（旧进程要等新的起来才停）。
  退回之后引擎下拉上显示的还是旧那家——错误由横幅说明，不假装换成了。
